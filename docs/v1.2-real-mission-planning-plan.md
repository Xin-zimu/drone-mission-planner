## 1. 计划定位与版本边界

### 1.1 核心判断

当前平台已具备地图编辑、任务分配、覆盖规划、三维航点、动态仿真、风险报告、回放、设备库和项目恢复能力。下一轮建设的主要收益，应来自规划结果的可信度和业务闭环，而不是继续增加独立面板。

本计划聚焦三个问题：

1. **规划的数据是否一致？** 编辑、分配、仿真、报告、导出必须读写同一份航线事实。
2. **规划的约束是否完整？** 到达时间、服务时间、等待时间、任务依赖、能源和返航必须共同决定可行性。
3. **规划的结果能否核验？** 坐标、高程、飞控动作、数据来源和验证记录必须能够追溯。

### 1.2 与既有路线图的关系

既有 [future-roadmap.md](future-roadmap.md) 保留 M6–M20 的实施历史。其“已完成核心实现”描述的是原定范围，不表示已经具备严格 VRPTW、完整 GIS 或经过目标飞控验证的任务执行能力。

本计划使用 `V12-0` 至 `V12-7` 编号，避免复用旧里程碑；后续开发排期优先采用本文。历史路线图不回写成“所有能力尚未开发”。

### 1.3 两种可交付范围

| 范围 | 完成阶段 | 适合用途 | 交付边界 |
|---|---|---|---|
| 演示与算法增强版 | V12-0～V12-3 | 课程设计、产品演示、离线方案研究 | 航点统一、调度闭环、全局多机分配；本地坐标输出仍不可直接用于飞行 |
| 真实任务准备基础版 | V12-0～V12-7 | 有明确数据来源和目标飞控的任务准备 | 增加地理校准、地形、围栏、导出校验和选定配置的 SITL 验证 |

**推荐以第二种范围作为 v1.2 正式目标，以第一种作为中途可发布的预览版本。**

“任务准备基础版”不是通用适航认证。本文中的执行兼容性始终限定于已记录的机型、固件、地面站版本、坐标基准和动作集合；未经验证的组合不能自动继承结论。

### 1.4 v1.2 必须完成

- `waypoints` 成为航线几何和动作的唯一权威数据，二维路径只读派生。
- 任务最早开始、完成截止、服务时长、累计 ETA、等待和依赖进入规划与仿真。
- 引入可替换求解器接口，接入 OR-Tools，保留经过同一约束校验的贪心基线。
- 支持异构无人机、多个起终点、跨搜索区域复用和整条路线的资源核验。
- 支持明确基准的 WGS84、本地 ENU、投影数据转换及坐标来源记录。
- 支持 GeoTIFF DEM、基础空间拓扑、带洞区域、多部件数据和独立航线导入。
- 建立可拒绝不合格方案的地理导出流程，并完成至少一个目标配置的地面站与 SITL 验证。
- 完成旧项目迁移、报告追踪、故障重规划一致性和 Windows 发布回归。

### 1.5 后续版本实施

- 完整多机 CBS、窄通道全局管制、复杂死锁处理。
- 分层三维搜索及稀疏 3D 搜索、固定翼可行轨迹。
- 加速度、转弯半径、时变阵风、传感器、链路与定位误差模型。
- 充电、换电、装卸、共享补给资源和完整多架次优化。
- 场景比较、敏感性分析、Monte Carlo 故障仿真。
- D* Lite/LPA* 等路径增量更新；以性能剖析和动态场景收益为前提。

### 1.6 不作为本轮默认交付

- 真实飞控在线连接、实时指令下发、遥测接管、ROS 2 联动。
- 自动获取实时法规、在线空域授权或自动批准飞行。
- 跨平台、跨机型的全命令兼容；默认先限定多旋翼和最小命令集合。
- 在线地图账号、商业影像订阅、云端调度及在线 DEM 下载。
- 仅因新增 GIS 能力就重写全部 UI 或替换现有渲染框架。

## 2. 现状核验与缺口清单

### 2.1 代码证据

以下判断来自 2026-09-06 当前工作区静态核对，不代表重新执行了所有既有功能验收。路径均相对仓库根目录；实施时优先按符号定位，避免依赖会漂移的行号。

| 项目 | 当前事实 | 对实施的影响 | 主要证据 |
|---|---|---|---|
| 软件与数据版本 | 软件 `1.1.0`；项目格式 `1.6` | 软件 v1.2 不等于文件格式 1.2，格式升级需单独编号 | `pyproject.toml`；`persistence/project_repository.py:CURRENT_VERSION` |
| 航线双表示 | `Drone` 同时有 `planned_path` 和 `waypoints` | 存在多入口同步负担和任务关联丢失风险 | `domain/models.py:Drone` |
| 三维航点 | 已有高度模式、速度、动作、等待和任务引用 | 应收敛既有模型，不再重复新增一套基础航点 | `domain/waypoint.py:Waypoint` |
| 最早开始 | `MissionTask.earliest_start` 已有字段；分配模块未使用 | 需要规划器、解释器和仿真共同落实 | `domain/models.py:MissionTask`；`planning/assignment.py` |
| 截止时间 | 当前以 `route.estimated_time - task.deadline` 计算惩罚 | 不是累计完成时间硬约束 | `planning/assignment.py:GreedyAssignmentPlanner.assign`、`_explain_candidate` |
| 执行时间 | `execution_duration` 已进入部分能耗及航点停留逻辑 | 不能描述为“完全未使用”；需要统一计时，避免重复计入 | `planning/assignment.py`；`planning/route_planner.py` |
| 分配方法 | 按任务顺序选择局部最低代价候选 | 无完整联合任务顺序与多机调度优化 | `planning/assignment.py:GreedyAssignmentPlanner` |
| 多区域复用 | 多区域应用结果时采用 `assigned` 集合，每机只接收首份非空区域路径 | 需改变“区域分别规划、直接覆盖航线”的应用方式 | `ui/main_window.py:plan_all_coverage_areas` |
| GIS 导入 | GeoJSON/KML 接口以本地米制解释；基础几何导入存在 | 需要显式区分历史本地格式与标准地理格式 | `persistence/mission_import.py` |
| 带洞覆盖 | `SearchArea.holes` 和扣洞扫描算法已有实现 | 缺口主要在完整导入、拓扑检查与多部件映射 | `domain/models.py:SearchArea`；`planning/coverage.py` |
| DEM | CSV/规则网格地形已存在；`load_from_dem` 抛出 `NotImplementedError` | 需要标准栅格适配器和有效性掩膜 | `domain/terrain.py`；`persistence/terrain_import.py` |
| 地形越界 | 网格采样会钳制到边缘；部分异常回退到基础高度 | 真实任务模式不能把未知区域当作已知地形 | `domain/terrain.py:TerrainModel._grid_altitude_at` |
| 飞控格式导出 | QGC/WPL 导出明确携带本地坐标与不可直接飞行说明 | 存在格式写入能力，尚无完整地理执行验证链 | `persistence/route_export.py` |
| 协同避碰 | 有时空采样预约、优先等待及冲突复查 | 需要建立对首段、迎头、长驻留、死锁的严格回归和后续升级 | `planning/deconfliction.py` |
| 依赖 | `ortools`、`numpy`、`networkx`、`pyqtgraph` 已声明 | 按实际用途审计，不因已声明就强行使用 | `pyproject.toml` |

## 3. 产品目标与验收指标

### 3.1 核心用户流程

1. 新建本地项目，或选择具有来源与精度信息的地理基准。
2. 导入任务、区域、DEM 和影像，预览范围及异常，确认后事务式写入。
3. 配置机队、基地、任务时间窗、依赖、载荷、能源和围栏。
4. 运行规划，获取航线、任务时间表、未分配原因和求解状态。
5. 查看甘特图及地图联动，理解等待、延迟、分配和返航安排。
6. 仿真执行，对照计划与实际时间，遇到故障从现场状态重规划。
7. 选择目标飞控配置，运行最终校验，生成航线与验证清单。
8. 在指定地面站和 SITL 中核验文件及动作，保存版本和结果证据。

### 3.2 建议量化指标

以下数值是项目拟定验收目标，不是现有性能结论。V12-0 固定测试机器、数据和版本后调整一次；后续调整必须记录原因。

| 维度 | 目标 | 验证方法 |
|---|---|---|
| 数据一致性 | 正常业务代码不再直接维护第二份二维航线 | 写入口搜索、服务层测试、保存加载检查 |
| 旧项目兼容 | 仓库所有历史有效样例可迁移，异常冲突有明确报告 | 按文件格式版本建立迁移矩阵 |
| 时间窗 | 所有标记为严格可行的方案均满足最早开始和完成截止 | 独立时间递推核验器 |
| 依赖 | 全部已执行后继的前置任务均已完成 | DAG 与仿真事件断言 |
| 时间一致性 | 在共享确定性运动模型下，计划/仿真偏差不超过明确累计的离散误差预算 | 按任务数、积分步长与整数缩放计算误差上界 |
| 能源 | 飞行、爬升、等待、执行、返航及安全余量计入整条路线 | 分项账本与独立复算 |
| 分配质量 | 固定对比集上，同预算最终候选不劣于通过核验的贪心候选 | 两种解统一按字典序目标评价后择优 |
| 坐标数值 | 在声明局部范围内，双向数值转换水平误差建议不超过 0.01 m | 固定参考点、独立参考结果和往返测试 |
| 地理精度 | 明确呈现源数据精度；数值往返精度不当作定位精度 | 导入报告与独立控制点残差 |
| DEM | NoData、覆盖范围外和未知垂直基准不能默认为安全地形 | 缺口与边界样例 |
| 导出 | 不满足目标配置、地理基准或硬约束时拒绝执行用途导出 | 正向及阻断场景 |
| UI | 规划、栅格导入和最终核验不长期阻塞主线程；可取消 | UI 操作与取消回归 |
| 可追溯 | 每份验证结果对应输入、方案、环境和目标配置版本 | 哈希及版本失效测试 |

### 3.3 不用单一风险分数替代可行性

规划结果分开记录：

- `hard_constraints_passed`：已实施硬约束是否全部通过。
- `unsupported_constraints`：输入中哪些约束当前无法建模或执行。
- `warnings`：源精度、保守近似、软截止迟到等信息。
- `solver_status`：可行、已证明最优、已证明不可行、超时未知、取消或错误。
- `validation_status`：未验证、已验证、验证失败或因输入变化失效。

分数较低不允许覆盖硬约束失败；没有发现可行解不自动等于证明不可行。

## 4. 总体架构与数据闭环

### 4.1 建议的数据流

```text
任务 / 机队 / 地理基准 / 地形 / 围栏
                    ↓
             ProjectSnapshot
                    ↓
         输入与能力范围检查
                    ↓
       航段生成与 TravelCostProvider
                    ↓
        Scheduler / AssignmentSolver
                    ↓
           MissionPlan 候选方案
                    ↓
       协同冲突调整 / 完整约束复核
                    ↓
          原子应用到 ProjectService
             ↙              ↘
   仿真 / 回放 / 报告       目标导出校验
             ↓                  ↓
       实际执行记录        文件 + manifest
             ↓                  ↓
       计划与实际对比       地面站 / SITL 验证
```

### 4.2 单一事实与派生数据的边界

| 数据 | 权威来源 | 可派生内容 | 禁止行为 |
|---|---|---|---|
| 航线位置、高度、速度及动作 | `RoutePlan.waypoints` | 二维投影、剖面、轨迹采样 | UI 私自写另一份 `planned_path` |
| 任务业务要求 | `MissionTask` | 任务动作和服务区间 | 将任务执行时间在航点和时间表中重复累计 |
| 计划时间 | 调度器生成的 `TaskSchedule` / `RouteTimeline` | 甘特图、ETA 标签 | 各面板自行累计并形成不同口径 |
| 实际时间 | 仿真事件与运行态 | 实际甘特、延误统计 | 用实际时间覆盖原始计划后失去对照 |
| 地理参考 | 项目级 `GeoReference` | 地理坐标显示、栅格重投影 | 靠坐标数值范围猜测投影 |
| 导出状态 | 指定快照的校验记录 | 导出按钮可用性 | 修改航线后继续沿用旧的通过标记 |

`waypoints` 作为唯一航线来源，不意味着把任务要求、仿真状态和校验记录都挤入航点。它们是不同语义的数据，通过稳定 ID 与版本关联。

### 4.3 建议新增对象

| 对象 | 建议字段 | 说明 |
|---|---|---|
| `RoutePlan` | `id`、`revision`、`drone_id`、`waypoints` | 唯一航线容器；可先由现有 `Drone.waypoints` 平滑演进 |
| `MissionPlan` | `id`、`input_revision`、`routes`、`schedules`、`solver_metadata` | 一次完整规划的不可变结果快照 |
| `TaskSchedule` | `task_id`、`drone_id`、`arrival`、`start`、`finish`、`departure`、`wait_reason` | 明确区分到达、开始、完成和离开 |
| `PlanningContext` | `mission_time`、实时位置/高度/能源、已完成任务、锁定任务 | 初次规划与故障重规划共用上下文 |
| `ConstraintViolation` | `code`、对象 ID、时间/航段范围、期望值、实际值、建议 | 可用于 UI、报告和导出 |
| `GeoReference` | 水平 CRS、ENU 原点、原点高度基准、轴约定、适用范围、精度、来源 | 地理转换的唯一配置 |
| `TerrainSample` | `elevation`、`valid`、`source_id`、`resolution`、`uncertainty` | 有效性不能只由一个浮点数表达 |
| `ExportProfile` | 飞控/固件/机型/地面站版本、命令白名单、高度帧、限制 | 明确输出兼容范围 |
| `ValidationManifest` | 输入/方案/地形/配置哈希、校验结果、时间、工具版本 | 避免验证结果脱离具体数据 |

这些名称属于目标设计。V12-0 应先形成简短架构决策，再逐阶段引入，避免一次性创建大量空类。

### 4.4 计划失效规则

下列变更使相关缓存、时间表或验证结果失效：

- 航点位置、高度模式、动作、速度、停留时间改变。
- 任务时间窗、执行时长、优先级、依赖或载荷要求改变。
- 无人机速度、能源参数、起点、高度、状态、基地改变。
- 地形、地理原点、投影、围栏、障碍物、风场改变。
- 避碰插入等待、路径平滑修改轨迹、重规划替换未执行部分。
- 求解模型版本、目标飞控配置或校验器规则发生变化。

异步结果提交前必须比较 `input_revision`。过期结果不能覆盖用户的新编辑；取消和失败不产生半份规划结果。

## 8. 阶段 V12-2：时间窗、累计 ETA 与任务依赖

### 8.1 目标

在接入优化求解器之前，先实现独立且正确的时间与资源核验器，并让现有贪心规划、仿真、解释与报告使用同一套语义。

### 8.2 时间语义

| 字段 | 定义 |
|---|---|
| `earliest_start` | 任务服务允许开始的最早任务时刻；为空表示无额外下界 |
| `deadline` | 任务服务必须完成的最晚时刻；为空表示无额外上界 |
| `execution_duration` | 单次任务服务持续时间；不能由 UI 重复换算 |
| `arrival_time` | 到达任务执行位置、满足执行高度的时刻 |
| `start_time` | 满足时间窗、任务依赖和资源条件后真正开始服务的时刻 |
| `finish_time` | 服务完成的时刻 |
| `departure_time` | 完成服务及明确的离场等待后开始下一航段的时刻 |
| `wait_seconds` | 本任务服务之外的等待；带原因及地点 |
| `lateness` | `max(0, finish_time - deadline)`，仅软截止允许非零 |

首版新增任务默认使用“完成截止 + 硬约束”。历史 deadline 曾作为评分项，应迁移为明确的 `legacy_soft`/软截止状态并提示重新确认，不能把旧项目无声升级为已满足硬约束。

### 8.3 累计公式

对无人机 d 的任务序列，设上一任务离开时刻为 `D_prev`，航段时间为 `T_leg`，最早开始为 `E_i`，全部前置完成时刻的最大值为 `P_i`，服务时间为 `S_i`：

```text
A_i = D_prev + T_leg                         # 到达
B_i = max(A_i, E_i, P_i)                     # 开始服务
W_i = B_i - A_i                             # 到达后的等待
F_i = B_i + S_i                             # 完成服务
D_i = F_i + explicit_post_service_hold_i     # 离开
硬截止：F_i <= deadline_i
```

无时间下界或无前置时不引入额外限制。第一次出发以 `PlanningContext.mission_time` 和起飞准备时间为起点；故障后不能重置到零。

`T_leg` 必须包含当前运动模型实际采用的水平移动、升降和动作转换规则。若允许同时升降和平移，不能盲目把水平时间和垂直时间相加；若仿真分阶段执行，规划也应采用同一规则。

### 8.4 必须固定的回归示例

无人机在 `t=0` 出发：

| 项目 | 任务 A | 任务 B |
|---|---:|---:|
| 从上一位置的航行时间 | 30 s | 20 s |
| 最早开始 | 60 s | 120 s |
| 执行时长 | 40 s | 30 s |
| 完成截止 | 110 s | 140 s |
| 前置任务 | 无 | A |

正确结果：

1. A 在 30 s 到达，等待 30 s，60 s 开始，100 s 完成。
2. B 在 120 s 到达并开始，150 s 完成。
3. B 超过完成截止 10 s，硬截止模式必须判为不可行。
4. 仅比较 B 的 20 s 单段航行时间会误判。
5. A 的 30 s 等待和两项服务时长均须计入能源，服务不能重复计费。

### 8.5 任务依赖

建议先支持完成到开始（Finish-to-Start）依赖：

- `predecessor_ids: list[str]`：所有前置必须完成。
- 可选 `min_lag_seconds`：前置完成后至少间隔多久；无则为零。
- 可选同机要求作为独立约束；不能将“前置”一概解释为同一无人机执行。
- 校验缺失 ID、自引用、重复边和环路。
- 错误信息显示具体环路，例如 `A → B → C → A`。
- 前置失败或取消后，后继进入阻塞状态；是否解除依赖由明确业务操作决定。
- 已完成前置沿用真实完成时刻，不重新计划一次。
- 执行中的任务声明是否可中断；不可中断任务在重规划中锁定剩余服务区间。

### 8.6 等待策略

到达过早不总适合原地悬停。首版至少区分：

| 等待类型 | 允许位置 | 资源处理 |
|---|---|---|
| 基地延迟出发 | 已着陆且允许占用的基地 | 计入地面待机能耗和基地占用 |
| 空中等待 | 通过空间和高度校验的等待点 | 计入悬停能耗和时空占用 |
| 服务前等待 | 任务附近合法位置 | 与任务执行时间分开 |
| 冲突让行 | 通过避碰器确认的等待点 | 重算后续 ETA、能源与截止 |

等待点不安全时，应延迟出发、重新选点或拒绝方案；不能为满足时间窗直接在禁飞区停留。

### 8.7 能源和载荷计量

- 统一飞行、升降、服务、等待、返航的单位和账本。
- 如果功率用 W、时间用 s、容量用 Wh，则该项能量按 `P × t / 3600` 计算。
- 历史 0～100 归一化电量不能直接当作 100 Wh；真实任务模式要求有效容量和参数来源。
- 安全储备是可行性余量，不是每条航段都要扣除一次的实际消耗。
- 首版将载荷要求区分为设备/能力要求和物流消耗。未实现取送载荷变化时，不宣称已支持动态配送容量。
- 整条路线终点与合法返航点必须一致；不能每个任务都假设还能返回，却漏掉最终实际返航。

### 8.8 仿真和报告闭环

- 仿真增加可识别的“等待时间窗”“等待前置”“执行任务”原因。
- 任务完成事件只在服务结束后产生，不能到达即完成。
- 记录计划与实际的到达、开始、完成时间，报告展示偏差及原因。
- 暂停、单步和播放倍率不改变逻辑时间语义。
- 重规划保留任务时钟、已完成服务、现场位置/高度/能源、故障状态和覆盖历史。
- 运行时新增让行或故障使计划失效时，显示变更并重算，不能继续展示过期 ETA。

### 8.9 甘特图最小范围

- 每机一行，显示起飞、航行、等待、服务、返航区间。
- 任务服务块展示任务名、开始、完成、截止及是否迟到。
- 区分计划与实际；显示时间窗和当前任务时刻。
- 点击任务块定位地图与属性面板。
- 超期、依赖阻塞、未分配状态可筛选。
- 首版只读；拖动修改调度后续再做，避免产生新的隐式写入口。

### 8.10 测试与验收

- [ ] 空时间窗、零时长、恰好到截止、恰好超过截止、非法负数与 NaN。
- [ ] 同机累计、跨机依赖、环路、取消与失败传播。
- [ ] 长等待导致电量不足；返航和安全储备仍满足。
- [ ] 服务时间仅累计一次。
- [ ] 避碰插入等待后重新检出超期。
- [ ] 现场重规划时刻不是零。
- [ ] 甘特、解释器、仿真与报告来自同一时间对象。

## 9. 阶段 V12-3：全局多机任务优化

### 9.1 目标与范围

引入 OR-Tools 统一优化任务所属无人机和访问顺序，保留原贪心算法作为可比基线及明确标识的降级选项。

首版范围：

- 多无人机、多个基地/起终点、异构速度和能源参数。
- 单架次内多个任务，以及同一无人机跨区域连续执行。
- 时间窗、服务时长、能力匹配、返航及安全储备。
- 受支持的任务前置关系及已锁定任务。
- 可选任务允许带惩罚不分配；必做任务不能静默丢弃。

完整充电、共享换电站及多架次调度放在后续阶段，不把“同一次飞行覆盖多个区域”写成“已经实现补能多架次”。

### 9.2 算法接口

建议实现以下接口/结果，名称可在 V12-0 调整：

```text
AssignmentSolver.solve(snapshot, context, settings) -> PlanningResult
TravelCostProvider.get(drone_profile, origin, destination, environment_revision)
ScheduleEvaluator.evaluate(candidate, context) -> EvaluationResult
PlanValidator.validate(candidate, snapshot) -> ValidationResult
```

`PlanningResult` 至少包含方案、未分配任务、拒绝原因、求解状态、耗时、求解配置、模型版本和使用的近似。

### 9.3 模型选择

OR-Tools 的 VRPTW 示例使用旅行时间矩阵、时间维度和时间窗构建车辆路径问题，可作为基础适配器参考；本项目的跨机依赖、能源和覆盖块仍需单独建模与验证。[OR-Tools VRPTW 官方文档](https://developers.google.com/optimization/routing/vrptw)

建议分层：

1. Routing 模型优先处理路径顺序、车辆选择和基础时间窗。
2. 受支持的前置关系显式加入约束，不依赖任务排序碰巧满足。
3. 对共享资源、复杂跨机服务和未来多架次，评估 CP-SAT 调度层或统一 CP-SAT 原型。
4. 暂时无法精确表达的约束必须明确拒绝或使用保守模型，不能在 UI 保留字段却让求解器忽略。
5. 整条候选路线始终经过独立核验器，不能用求解器返回非空作为最终通过标准。

### 9.4 航段代价矩阵

矩阵元素不是简单欧氏距离，至少包含：

- 安全路径是否存在、路径几何、总距离。
- 与机型一致的旅行时间和高度变化。
- 当前风场下的方向性代价；不强制对称。
- 估计能源及其保守上下界/适用条件。
- 地形、障碍、围栏和机型参数版本。

对不同速度、半径、爬升率和载荷能力的无人机，不能共用一份未经区分的矩阵。

不可达边采用显式禁止或受控不可达表示，避免随意大常数溢出或仍被求解器选中。

### 9.5 整数缩放与时间语义映射

- 内部业务时间可使用浮点秒，求解器时间采用明确整数刻度，例如 0.1 s。
- 旅行和服务时间向上取整；最早开始向上取整；截止向下取整，避免舍入创造虚假可行性。
- 本计划 deadline 约束的是完成时刻；若模型维度代表服务开始，需用 `deadline - service_duration` 转换上界。
- 将服务时间只放在一个确定位置，例如离开节点的 transit，避免重复计入。
- 为等待设置明确的 slack 与规划 horizon，不使用无意义的无限上界。
- 检查目标权重、惩罚和时间刻度的整数范围。

### 9.6 能源约束处理

总能源会随等待、风、高度和载荷变化，并不天然等于静态弧代价之和。

首版建议：

1. 弧代价采用适用机型和已知载荷下的保守估计。
2. 对等待和服务的能源单独建模或预留明确上界。
3. 对候选结果做逐段能源复算，并验证最终返航余量。
4. 若复算失败，加入约束/调整预算再求解，设置最大修复次数。
5. 超过修复预算返回未找到可验证方案，不能输出“优化成功”。

依赖起飞时间的风场和复杂物流载荷尚未支持时，结果必须注明采用的静态假设。

### 9.7 目标函数

建议按优先级逐层优化，避免单个随意权重把安全、必做任务和距离混在一起：

1. 所有硬约束成立。
2. 必做任务全部完成；允许部分规划时单独标为“部分方案”。
3. 最大化可选任务的优先级收益。
4. 最小化软截止迟到。
5. 最小化整体完成时刻（makespan）。
6. 最小化总能源、总距离和不必要等待。
7. 以负载均衡和稳定排序作为次要偏好。

如最终实现加权目标，需记录每项单位、归一化方式与上界，证明低优先级指标不能覆盖高优先级目标。

### 9.8 多区域复用

将搜索区域分解成可分配覆盖块，而不是先给每个区域永久占用无人机：

1. 复用已有带洞扫描能力，生成若干完整扫掠条带/任务块。
2. 每块包含入口、出口、允许扫描方向、服务轨迹、持续时间、能力和覆盖收益。
3. 方向选择必须把入口与出口成对绑定，不能分别选出不可能的组合。
4. 联合考虑点任务、覆盖块和区域之间转场。
5. 同一机可执行 A 区块、B 区块并返航，前提是累计约束满足。
6. 覆盖率从实际覆盖轨迹/单元计算；不能以“分配了该区域”代替覆盖完成。
7. 对区域分块后的全局优化，仅宣称在固定分块表示上的优化，不宣称覆盖形状和航线的绝对全局最优。

### 9.9 与避碰的闭环

```text
分配与排程 → 候选航线 → 冲突调整
                            ↓
           重算时间窗 / 能源 / 前置 / 返航
                            ↓
       通过则应用；失败则修复或重新求解
```

设置总求解时限和最大迭代次数。冲突未解决、等待造成超期或能源不足时，返回具体失败原因。禁止通过不断增加等待把界面卡住。

### 9.10 降级与求解状态

| 情况 | 行为 |
|---|---|
| 优化器返回已验证可行解 | 与已验证贪心候选比较，保留更优者 |
| 达时限但已有可行解 | 返回“时限内可行，未证明最优” |
| 达时限且无解 | 返回“未找到可行解”，允许用户显式查看受同样约束检查的基线候选 |
| 已证明不可行 | 返回不可行及可提取的冲突信息 |
| 依赖包不可用 | 清晰显示优化器不可用；可使用明确标识的基线模式 |
| 用户取消 | 保留原项目状态，不应用部分候选 |
| 输入版本改变 | 丢弃过期结果并提示重算 |

并非所有求解器都会给出完整不可行核心。缺少证明时，解释应表述为“已发现的冲突”或“候选被拒绝的原因”。

### 9.11 测试与验收

- [ ] 小规模任务通过穷举或独立精确模型核对目标和可行性。
- [ ] 存在固定贪心劣解场景，优化后严格改善且没有遗漏硬约束。
- [ ] 同预算候选择优确保最终结果不劣于有效基线。
- [ ] 异构能力、多基地、不可达边、长服务时间、硬截止全部生效。
- [ ] 同一无人机连续覆盖两个独立区域。
- [ ] 部分完成任务和已锁定任务不被重复分配。
- [ ] 超时、取消、包缺失和输入变更均有测试。
- [ ] 固定输入、版本和配置可复现结果；若墙钟时限/并行求解影响精确复现，记录该限制。

## 10. 阶段 V12-4：地理坐标与空间约束

### 10.1 目标

为真实任务建立完整坐标语义，同时保留不要求地理数据的本地演示项目。

### 10.2 坐标体系

| 层次 | 数据 | 用途 |
|---|---|---|
| 输入源坐标 | 源 CRS、轴顺序、单位及原始几何 | 可追溯和重新导入 |
| 地理参考 | 经度、纬度及明确垂直基准的高度 | 地理定位和外部交换 |
| 地心坐标 | ECEF，作为需要时的转换中间层 | 严谨的局部坐标变换 |
| 规划坐标 | 本地 ENU，x 东、y 北、z 上 | 米制距离、路径和局部几何 |
| 屏幕坐标 | Qt 视图坐标 | 处理屏幕 y 向下与地图北向 |

地理水平坐标、椭球高、海拔高、相对起飞点高度和 AGL 分开建模。单独写“EPSG:4326”不能解决所有高度问题。

### 10.3 地理基准配置

- `mode`：`local_only` 或 `georeferenced`。
- 源/目标水平 CRS 描述，优先保存规范标识及可复现定义。
- ENU 原点经纬度、椭球高，以及高度来源和不确定度。
- 真北与本地/屏幕轴关系；历史画布 y 向下需显式变换。
- 已验证适用范围及局部近似误差预算。
- 垂直基准、地球重力模型/网格版本及离线数据可用性。
- 校准控制点、拟合残差、独立检核点误差和确认时间。

转换可使用 `pyproj.Transformer`；轴顺序和 `always_xy` 选择需要在适配器中固定并测试，不能让不同入口自行决定。[pyproj Transformer 文档](https://pyproj4.github.io/pyproj/stable/api/transformer.html)

### 10.4 本地项目校准与重定位

两种操作必须分开：

1. **给既有本地几何赋予地理参考**：确定原点、方向、比例和高度来源，不把米数直接当经纬度。
2. **更换 ENU 原点但保持真实位置不变**：先保留真实地理位置，再重算所有本地坐标；任务、基地、路线、围栏、DEM 和底图一起变换。

导入向导展示变换前后范围和控制点残差。两点比例尺校准仅能支持受限变换，不等于消除影像所有误差；建议至少增加独立检查点。

### 10.5 高度语义

必须区分：

- 椭球高：地理三维转换使用的高度。
- 正高/特定海拔基准：DEM 或飞控常用，但需知道具体基准。
- AGL：相对当前位置地形的高度。
- 相对 home 高度：相对任务起飞参考点，不能等同于 AGL。

实现要求：

- 不因字段名叫 `MSL` 就认为其数值已经完成垂直基准转换。
- 高度转换缺少所需网格或源基准未知时，阻止受影响的执行用途导出。
- 将 AGL 转成固定海拔航点时沿航段加密采样并保守检查，不能只检查两端。
- 对起飞点变化使相对高度含义变化的情况，令旧导出验证失效。
- 将地形分辨率和不确定度纳入 clearance 余量。

### 10.6 地理围栏和空间硬约束

建议增加或扩展 `Geofence`：

- 允许区/排除区类型。
- Polygon/MultiPolygon 及孔洞。
- 下界、上界及高度基准。
- 可选生效时间区间；当前求解器不支持时显式拒绝该严格约束。
- 来源、更新时间、精度和备注。

检查对象包括航点、完整航段、等待点、起降位置和返航路径。边界缓冲应考虑机体半径、定位与数据误差；不能只检查折线顶点。

v1.2 仍可使用保守二维规划：对无法证明可以越过的体积障碍当作不可穿越。会漏掉部分三维可行解，但不能把后置风险失败的航线标为通过。

### 10.7 测试与验收

- [ ] ENU 原点映射为零，东西南北轴与预期一致。
- [ ] 常见投影、不同半球、边界范围、非法经纬度和轴交换样例。
- [ ] 独立控制点检核；往返精度与真实定位精度分开报告。
- [ ] 屏幕拖动方向与地理北向一致。
- [ ] 更换原点后对象真实位置保持不变，校验缓存失效。
- [ ] 未校准项目不能生成执行用途的地理航线。
- [ ] AGL、海拔和相对 home 混淆有针对性阻断测试。

## 11. 阶段 V12-5：真实地形与完整空间数据导入

### 11.1 总体导入管线

```text
读取与限额检查 → 格式解析 → 坐标/高度识别
             → 拓扑与数值检查 → 重投影/裁剪
             → 范围预览及问题清单 → 用户确认
             → 单次事务导入 → 来源记录与缓存失效
```

预览取消不改变项目；确认时核对预览基于的项目版本，避免导入期间用户编辑导致范围错配。

### 11.2 GeoJSON / KML

标准 GeoJSON 采用 WGS84 地理坐标语义；当前项目的本地米制 GeoJSON 需要显式列为历史兼容模式，不能继续以同一入口无提示解释。[RFC 7946](https://datatracker.ietf.org/doc/html/rfc7946)

| 输入形态 | 建议处理 |
|---|---|
| Point / MultiPoint | 按配置映射任务点或独立点对象 |
| Polygon 外环 + 洞 | 完整保留外环和内环，导入前检查洞的合法关系 |
| MultiPolygon | 首版可拆成多个区域，保留共同 `source_feature_id` 与 `part_index` |
| 单条 LineString | 建立独立航线对象，保留顶点顺序 |
| 多条独立 LineString | 逐条建立航线；绝不自动连接最后一点与下一条起点 |
| MultiLineString | 按部件拆分，保留来源关系和顺序 |
| GeometryCollection | 明确支持列表；不支持成员显示为诊断，不能无声丢弃 |
| KML 多几何与内环 | 规范化到同一中间几何，并保留高度模式 |
| 历史本地米制数据 | 用户显式选择 legacy/local 模式，报告记录该解释 |

属性映射至少包括任务名称、优先级、时间窗、时长、依赖外部 ID、区域属性及航线 ID。先建立稳定外部 ID 到内部 ID 的映射，再解析跨对象引用。

### 11.3 拓扑检查

- 外环闭合、有效顶点数量、零面积和非有限坐标。
- 自相交、重复边、连续重复顶点。
- 洞是否在外环内部，洞间是否相交，洞与外环接触如何处理。
- 多部件区域是否意外重叠、重复 feature ID 是否冲突。
- 独立航线中的重复点不能因距离为零就删除：需比较高度、动作、服务和任务引用。
- 对边界接触采用明确精度容差，单位基于规划 CRS。
- 不自动执行可能改变业务范围的“修复几何”；修复需展示前后差异并保留原始来源。
- 一个文件同时包含有效和无效对象时，先给完整诊断；默认原子导入，有选择跳过时写入报告。

### 11.4 GeoTIFF / DEM

首版优先 GeoTIFF 高程栅格；SRTM `.hgt` 和其他 GDAL 支持格式作为明确扩展项，以样例和驱动验证为准。“DEM”是高程数据类别，不视为单一文件格式。

读取内容：

- 宽高、波段、数据类型、压缩方式、分辨率与空间范围。
- 水平 CRS、仿射变换、旋转项、像元解释。
- NoData、有效掩膜、scale/offset、垂直单位与基准。
- 源分辨率、数据时间、许可证/来源、内容哈希。

重投影建议由 `rasterio` 适配器处理，显式指定源/目标变换、CRS 和重采样方法。[Rasterio 重投影文档](https://rasterio.readthedocs.io/en/stable/topics/reproject.html)

### 11.5 地形采样策略

| 场景 | 策略 |
|---|---|
| 视图显示 | 允许降采样或较平滑插值 |
| 一般轨迹能耗 | 按声明的采样分辨率插值 |
| 安全净空 | 保守采样，考虑周围像元极值、分辨率及不确定度 |
| NoData | 返回未知/无效，不能自动置零 |
| 超出覆盖范围 | 返回未知，不能钳制到 DEM 边缘假装有效 |
| 多 DEM 交界 | 明确优先级、覆盖规则和基准一致性 |
| 旋转/非正方形像元 | 先正确变换或重采样，不套用单分辨率简式 |

将当前 `load_from_dem` 的实际文件读取放在 persistence/适配器层。领域模型不直接依赖 GDAL/rasterio；旧占位函数根据兼容需要委托或废弃。

### 11.6 大文件和离线资源

- 导入前显示预计像元数量、内存占用和裁剪范围。
- 使用窗口读取、任务范围裁剪、预览金字塔和缓存。
- 设置可配置上限；超限提供裁剪建议，不让应用直接耗尽内存。
- 不将大型栅格完整展开进 JSON 项目文件。
- 项目保存资源引用、相对路径和哈希；提供“打包项目资源”用于迁移机器。
- 外部 DEM 丢失时保留项目可编辑，但地形依赖规划与导出失效。
- 不静默联网下载投影或地球重力网格；离线依赖缺失明确报告。

### 11.7 正射影像与世界文件

- 支持有地理变换信息的正射影像及 PNG/JPG 配套世界文件。
- 世界文件描述像素到地图的变换，不足以单独确定 CRS；缺少 CRS 时要求配置。
- 支持旋转、像元中心与边界的区别，防止半像元偏移。
- 在预览中叠加任务、DEM 和控制点，显示范围与分辨率。
- 不把普通航拍照片自动认定为正射影像。
- 影像仅用于视觉参考；地形与障碍安全依据来自对应数据源。

### 11.8 验收场景

- [ ] 带两个洞的 Polygon 导入后保留洞，并在覆盖规划中正确扣除。
- [ ] MultiPolygon 分部件导入，可追溯到同一源对象。
- [ ] 两条独立 LineString 不出现跨对象连接段。
- [ ] 自相交、洞越界、缺 CRS、错误单位有清晰对象级错误。
- [ ] GeoTIFF 在已知点得到预期高程，包含旋转与 NoData 样例。
- [ ] 地形之外、缺失栅格或未知高度基准不能通过执行导出。
- [ ] 影像与控制点无未经解释的翻转、平移和半像元偏移。
- [ ] 导入、撤销、重做、保存、重开结果一致。

## 12. 阶段 V12-6：目标飞控航线导出与验证

### 12.1 目标

将“能写出 `.plan` / WPL 文件”升级为“能够针对明确目标配置生成地理航线，验证命令语义，并保留证据”。

首发建议选一个 PX4 多旋翼配置及指定 QGroundControl 版本。ArduPilot/WPL 作为独立兼容目标验证，不能因共用部分命令就自动认定兼容。

### 12.2 输出类别

| 输出 | 允许条件 | 用途 |
|---|---|---|
| 内部 JSON / 检查 CSV | 本地项目也可输出，明确坐标模式 | 调试、审阅、离线交换 |
| 历史本地 QGC/WPL 检查文件 | 保留兼容时必须明确隔离和不可执行标记 | 历史演示，不进入执行流程 |
| 地理任务文件 | 地理基准、高度、硬约束和目标配置全部通过 | 指定目标的任务准备 |
| 验证 manifest / 报告 | 与导出文件共同生成 | 追溯和结果核验 |

`.plan` 的任务结构、地理围栏等字段以目标版本规范为依据，不自行发明地面站会执行的字段。[QGroundControl Plan 格式](https://docs.qgroundcontrol.com/master/en/qgc-dev-guide/file_formats/plan.html)

### 12.3 ExportProfile

至少记录：

- 飞控类型、固件版本、机型类别。
- 地面站类型与版本、文件格式版本。
- 允许的导航、起飞、降落、悬停、速度和拍照命令。
- 支持的高度帧，以及 home/terrain 相关前置条件。
- 最大航点数、任务距离/高度/速度范围及目标参数快照。
- RTL 的处理方式、返航高度和受控范围。
- 围栏、等待、复杂动作和任务依赖的能力声明。
- 该配置最后一次完成导入与 SITL 验证的证据 ID。

### 12.4 导出前硬校验

1. 项目与方案版本一致，方案不是取消、部分写入或已失效结果。
2. 坐标有限、在有效范围内；真实地理参考与局部适用范围明确。
3. 高度基准已知，所需转换数据存在。
4. 整条航线和等待点通过地形、障碍、围栏及净空检查。
5. 起飞、返航和降落位置合法，终止行为明确。
6. 时间窗、服务时长和依赖按目标能力可表达或已有可靠执行机制。
7. 剩余能源、返航和安全余量充分；机型与单位已校准。
8. 所有命令、参数、速度和航点数量满足目标配置。
9. 多机时空冲突在声明假设下通过；未解决冲突不能标记通过。
10. 导出取值、重采样、格式精度变化后再核验一次最终几何。

### 12.5 调度计划与飞控任务的语义差异

这是 v1.2 必须显式处理的边界：

- 离线甘特图中的绝对开始时刻，不会因为写入自定义 JSON 字段就被飞控遵守。
- 固定悬停秒数不等于等待另一架无人机完成任务。
- 独立无人机任务文件无法凭任务 ID 建立运行时跨机同步。
- 避碰依赖同步起飞时刻时，需要声明起飞偏差预算并验证鲁棒性。
- 如果严格时间窗依赖当前尚未实现的在线调度，执行导出必须阻断该方案，或拆成具有明确外部执行前提的分阶段任务并保持“需外部协调”状态。
- 不能通过去掉任务依赖或时间约束让校验“通过”。

PX4 Mission 模式的任务检查和执行行为需按选定固件文档与实测核对；平台本地核验不能替代飞控自己的任务检查。[PX4 Mission 模式文档](https://docs.px4.io/main/en/flight_modes_mc/mission)

### 12.6 动作映射策略

| 平台动作 | 导出原则 |
|---|---|
| 普通飞行 | 映射受支持的导航点与明确高度帧 |
| 改变速度 | 按目标支持的命令和参数输出，不假设每航点自带速度会被读取 |
| 悬停 | 核对时长和到达判定语义 |
| 拍照 | 核对触发方式、命令顺序与相机能力；不把未支持动作悄悄转成飞行 |
| 扫描 | 展开为已核验轨迹及可支持的传感器动作 |
| 起飞/降落 | 明确地面状态、起飞高度和结束行为 |
| RTL | 不能假定飞控 RTL 等于规划器生成的返航折线；需验证实际 RTL 参数与轨迹，或采用经支持的显式返航路径 |

### 12.7 验证层级

| 级别 | 验证内容 | 必须保存的证据 |
|---|---|---|
| L0 | 字段、数值、文件结构 | 解析与校验报告 |
| L1 | 导出后重读、坐标及命令语义对照 | 航点/动作差异报告 |
| L2 | 指定地面站导入与地图/高度/动作检查 | 地面站版本、截图、导入结果 |
| L3 | 指定固件 SITL 执行 | 固件/配置、输入哈希、轨迹/事件日志、偏差报告 |
| L4 | 可选的人工现场验证 | 独立外场方案与记录，不列为本轮默认完成条件 |

L1 不能只用导出器同一段函数反向读取后自证正确。应使用独立参考夹具或目标工具；L2/L3 记录实际尝试，不能以格式测试代替。

### 12.8 导出包

建议输出：

```text
mission-export/
  drone-D01.plan
  drone-D02.plan
  manifest.json
  validation-report.html
  schedule.csv
  source-summary.json
```

manifest 至少包含方案 ID、各文件哈希、机型和配置、地理参考、DEM 来源、规则版本、硬检查结果、未支持项、生成时间及验证级别。

`flyable` 旧布尔字段应废弃或严格限定其兼容含义，改为分层状态，例如“本地检查”“地理校验通过”“指定配置 SITL 通过”。修改任何相关输入后重新验证。

### 12.9 验收

- [ ] 未校准、缺 DEM、未知高度基准、硬超期、能源不足、命令不支持均被阻断。
- [ ] 地理航点在地面站中位于预期区域，顺序、高度和动作正确。
- [ ] 导出后高度帧、单位和航点精度无隐式改变。
- [ ] 最小导航/起降任务及一个服务动作任务完成 L0～L3。
- [ ] 对跨机依赖、绝对时窗及 RTL 限制有失败场景与明确说明。
- [ ] 导出文件、报告和验证证据能追溯到同一个快照。

## 13. 阶段 V12-7：端到端集成与发布

### 13.1 综合场景

建立至少四个新的可复现场景：

1. **时间窗巡检**：两机六任务，含早到等待、服务时长、硬截止和一个依赖链。
2. **多区域资源复用**：三机、三个带洞搜索区域、异构载荷和一个紧急点任务。
3. **真实地形任务准备**：明确 CRS 的 DEM、正射影像、基地、围栏、AGL 与海拔混合输入。
4. **故障与再分配**：服务执行中故障，保留实际时间和完成状态，重规划剩余任务并使旧导出失效。

每个场景包含正常版本和故意不可行版本，以证明系统会正确拒绝。

### 13.2 发布内容

- 源码可运行版本和 Windows 本地包。
- 更新的软件版本、文件格式版本与迁移说明。
- 目标配置兼容矩阵和已验证动作列表。
- 时间窗/依赖、地理导入、导出验证的用户操作说明。
- 有来源与许可记录的小型样例数据。
- 自动化测试、性能基准、成品启动和 L2/L3 验证报告。
- 已知限制：局部地理范围、保守二维规划、真实参数要求、未实现在线同步等。

### 13.3 发布阻断项

- 正常编辑仍可能使航点与任务时间表静默失配。
- 有任一已标为严格可行的回归场景违反硬截止、依赖、能源或空间约束。
- 旧项目无备份被覆盖，或任务动作在迁移中无提示丢失。
- 未知地形、未知高度或不支持命令仍能进入执行用途导出。
- Windows 包缺失 OR-Tools/GIS 原生库或投影数据，核心工作流无法运行。
- 已承诺的目标配置没有地面站/SITL 证据。
- 规划、导入和校验的取消会破坏项目状态。

## 14. 后续 P1：协同避碰与真正三维规划

### 14.1 协同避碰分级实施

先用回归明确现有方法的边界，再升级搜索算法。

| 阶段 | 内容 | 关键验收 |
|---|---|---|
| C1 | 首航段、顶点冲突、迎头边冲突、等待占用与终点驻留 | 无起飞段漏检，无只查同时采样点的漏检 |
| C2 | Cooperative A* 的空间—时间预约，有限窗口与重排优先级 | 两机交叉、三机汇入可解决或可解释失败 |
| C3 | 通道检测、入口等待区、方向锁、租约与故障释放 | 窄通道内不安排相向进入 |
| C4 | 小规模 CBS/有界次优方案研究 | 小实例与精确解对照，大实例超时有返回 |
| C5 | 垂直分层和运行时局部避障 | 层间爬升下降同样参加冲突校验 |

必须处理：初始重叠、同基地起飞资源、终点停留、不同速度、不同安全半径、长时间悬停、等待点冲突、进退循环和故障机占道。

### 14.2 连续航段核验

- 采用相对运动的最近接近距离或具有明确误差界的自适应采样。
- 两点采样之间可能发生冲突，不能将采样无冲突等同连续时间安全。
- 水平/垂直距离阈值来自机体、定位和时间误差预算。
- 与调度闭环：插入等待或改变高度后重新校验窗口、依赖、能源和返航。
- 无法在预算内消解时返回失败及涉及机组，不能无限等候。

### 14.3 三维搜索首版

建议先实现分层图，再根据场景收益评估完整体素或稀疏 3D 搜索：

- 节点为 `(x, y, altitude_layer)`。
- 水平移动、爬升、下降和受限斜向移动构成边。
- 边代价包含时间、能源和合理的高度变化偏好。
- 节点和边都检查地形净空、障碍体积、空域上下界。
- 无人机爬升/下降率决定高度转换时间。
- 平滑后再次验证，不允许平滑穿越三维障碍。
- 可选择经验证的二维保守模式；降级路径也必须满足同一安全要求。

### 14.4 三维基准场景

- 低障碍：允许通过合法爬升后越过，验证相较二维绕行的收益。
- 高障碍与上方限高：必须水平绕行或明确无解。
- 山脊：地形净空连续满足，不能从两个安全端点穿过山体。
- 低空通道：只能在特定高度层通过。
- AGL 轨迹：地形快速变化时满足爬升率，无法满足则拒绝。
- 上下分层双机：垂直转换阶段仍不得相撞。

完成显示三维或给航点赋高度，不作为“完成三维搜索”的验收证据。

## 15. 后续 P1：仿真真实性

### 15.1 分阶段模型

| 阶段 | 增强 | 对规划的反向影响 |
|---|---|---|
| S1 | 加速度、减速度、最大爬升/下降加速度 | 航段 ETA 和停止距离变化 |
| S2 | 转弯半径、航向变化率、机型差异 | 折线可行性和轨迹平滑约束 |
| S3 | 时空风场、阵风、局部风障 | 时间相关旅行时间和能源 |
| S4 | 地形/障碍通信遮挡、带宽、延迟与丢包 | 中继位置和失联策略 |
| S5 | GNSS 偏差、随机噪声、传感器视场和探测概率 | 安全裕量、覆盖率和信息质量 |

### 15.2 设计要求

- 保留快速确定性模式，用于基础回归。
- 所有随机过程接受种子；环境、故障、传感器使用可分离随机流。
- 噪声随逻辑时间演进，不能依赖 UI 帧率或播放倍率。
- 区分真实状态、测量状态和控制使用的估计状态。
- 区分“地理覆盖过”与“满足传感器观测要求”。
- 对已有参数逐一说明单位、范围和适用机型。
- 用基准轨迹和可信日志校准参数；未校准模型在报告中说明用途。

### 15.3 验收

- 加速度和航向约束不会被航点切换跳过。
- 不可行的急转弯、上升率和极端逆风能被识别。
- 同一确定性配置在不同播放倍率下得到相同逻辑结果。
- 相同种子产生可复查的扰动；不同种子形成有意义分布。
- 更真实模型引起计划失效时，能反馈到规划和比较结果。

## 16. 后续 P2：多架次、补能与决策支持

### 16.1 多架次任务模型

建议对象：

- `Sortie`：所属无人机、开始/结束基地、航线、开始/结束时间。
- `ServiceStation`：充电、换电、装卸能力及并发容量。
- `BatteryPack`：容量、健康度、剩余电量和占用状态。
- `TurnaroundOperation`：换电、充电、载荷装卸与检查的持续时间。

### 16.2 核心约束

- 同一无人机多个架次不能时间重叠。
- 同一电池不能同时被两机使用，换下电池不会瞬间满电。
- 充电口、换电工位和载荷资源具有容量与排队。
- 前一架次结束、周转完成后才能开始下一架次。
- 周转和充电过程考虑非零时长，充电曲线根据需求分段近似。
- 完整规划 horizon 内任务窗口和依赖仍然成立。
- 中途补给必须有可到达的合法基地和足够到站余量。

### 16.3 算法建议

先实现单机多架次状态机，再接入固定周转时长和共享站点，最后联合优化。可评估 CP-SAT 的资源区间和路线层分解；不得仅复制虚拟无人机就忽略同一机体的时间互斥。

### 16.4 方案比较

每个方案保存不可变输入快照和指标，比较维度包括：

- 完成任务数、优先级收益、未完成原因。
- 总完成时间、最大延迟、总等待和依赖阻塞。
- 总能量、最小返航余量、架次数和补能占用。
- 总距离、覆盖率、重复覆盖及传感器有效覆盖。
- 最小安全间隔、通信中断和风险暴露时间。
- 求解耗时、近似条件和数据质量。

解释应来自真实指标差异，例如“方案 B 多使用一架无人机，使最晚完成时间减少 180 s，但能量增加 12%”，不能生成无法回溯到计算的数据。

### 16.5 参数敏感性与 Monte Carlo

- 敏感性：电池容量、风速、任务时窗、服务时长、安全间隔、故障时刻。
- 固定样本集或配对种子比较方案，减少随机差异干扰。
- 输出成功率、失败类型、时间/能源分位数、样本量和区间估计。
- 区分随机波动和模型本身的不确定性。
- 任务取消、提前停止和批量结果保存必须可恢复。
- 展示零失败时的统计限制，不将有限样本未失败解释成绝对可靠。

## 17. 工程改造、缓存与依赖治理

### 17.1 MainWindow 拆分

按实际业务改动逐步抽取，避免一次性移动约 2600 行代码：

| 建议控制器 | 职责 | 抽取时机 |
|---|---|---|
| `PlanningController` | 任务规划、覆盖、调度、求解进度、应用结果 | V12-1～V12-3 |
| `SimulationController` | 播放、暂停、事件、重规划和计划/实际同步 | V12-2 |
| `ImportExportController` | 预览、导入事务、导出检查和报告 | V12-4～V12-6 |
| `WorkspaceController` | 打开/保存、恢复、撤销和布局状态 | 根据被修改调用链渐进抽取 |

规则：

- 算法位于 `planning`，不放入控制器或 UI 类。
- `planning`、`simulation` 不依赖 PySide6。
- UI 控制器负责展示与交互，应用服务负责用例编排，领域对象保持业务语义。
- 若新增应用服务需要引用规划/仿真，先更新架构决策与 `developer-guide.md` 的允许依赖表，再实现。
- `ProjectService` 保持事务边界，避免多个控制器各自建立撤销栈。
- 重构阶段不顺手调整全部界面视觉和文本。

### 17.2 缓存

| 缓存 | Key 至少包含 | 失效条件 |
|---|---|---|
| 栅格地图 | 地图版本、分辨率、边界 | 几何或范围变化 |
| 障碍膨胀 | 障碍版本、机体半径、安全余量 | 对象或机型约束变化 |
| 地形采样 | DEM 哈希、坐标、算法/分辨率、垂直基准 | 数据/采样方法变化 |
| 航段几何 | 起终点、高度模式、机型空间参数、环境版本 | 障碍/围栏/净空规则变化 |
| 旅行时间和能源 | 航段、速度、风、载荷、电池模型版本 | 相关参数变化 |
| 坐标变换 | CRS 定义、原点、网格版本 | 地理配置变化 |
| 最终验证 | 完整输入/方案/目标配置哈希 | 任一相关输入改变 |

设定 LRU 或容量上限、命中率和耗时指标。缓存存在不能改变计算结果；测试比较缓存开/关的语义等价性。

### 17.3 空间索引与增量更新

- 先剖析是否主要耗时在碰撞查询、栅格构造或重复航段规划。
- 必要时为障碍、围栏、地形块引入空间索引，四叉树/R-tree 按数据特征选择。
- 动态事件先实现依赖清晰的缓存失效与局部重算。
- D* Lite/LPA* 只解决特定路径搜索的增量代价更新，不能替代任务分配、时间窗或多机冲突重排。
- 对变化范围较小的事件建立专门基准，证明确有收益后再替换全量 A*。

### 18.3 属性与模糊测试

建议验证的性质：

- 路线保存加载后语义等价，迁移两次结果不变。
- 任务序列增加非负服务时间，不应在同一路径和约束下提前后续最早完成时刻。
- 放宽一个时间窗不应使同一候选方案从可行变不可行。
- 增加安全余量不应扩大同一几何核验器的可行空间。
- 缓存开/关得到同一结果。
- 对支持区域内的参考点，坐标往返满足数值容差。
- 非有限数、过深嵌套、过大数组、损坏 XML/JSON、重复 ID 有受控错误与限额。

求解器启发式在固定时限内可能因搜索顺序不同找到不同质量结果，因此“约束放宽后求解器输出一定更优”不能作为未经条件限定的属性测试。

失败随机种子要固化成回归夹具；不能只报告“随机测试通过若干次”。

### 18.4 性能目标

以下为 V12-0 待校准的建议预算。冷启动矩阵构造、求解和后处理分开记录；求解时限不能冒充端到端耗时。

| 档位 | 规模 | 建议目标 |
|---|---|---|
| 小型 | 3 机、20 点任务、约 1 km 局部地图 | 热缓存规划约 3 s 内，交互可取消 |
| 中型 | 8 机、80 点任务、适量覆盖块 | 求解器预算 15 s，完整流程单独报告 |
| 大型 | 20 机、200 任务/覆盖块 | 求解器预算 60 s，允许返回可行候选和质量摘要 |
| DEM | 4096×4096 高程栅格 | 使用窗口/预览读取，不为每个视图复制全量数据 |
| UI | 规划或读取进行中 | 主线程保持操作响应，进度和取消可见 |

记录：机器、CPU、内存、Python/原生库版本、数据规模、冷热缓存、重复次数、P50/P95、峰值内存及失败率。
