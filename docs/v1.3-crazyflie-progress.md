# v1.3 Crazyflie Execution Progress

## CF7-HW Capability / Readiness Hardening

### Hardware Capability

Implementation PASS.

- Capability snapshot default output now resolves to
  `integrations/crazyflie_ros2/src/dmp_crazyflie_bridge/runtime/<robot>_capabilities.json`.
- Explicit `--config` paths fail closed when missing. Relative paths inside a
  config file resolve relative to that config file, not the operator's current
  working directory.
- cflib snapshots are schema-validated: `robot_id`, `uri`,
  `captured_at_utc`, `source=cflib_firmware_parameter_probe` and all five deck
  keys (`bcFlow2`, `bcZRanger2`, `bcLighthouse4`, `bcLoco`, `bcDWM1000`) are
  required. Missing deck keys no longer become `false`.
- Future timestamps beyond the small clock-skew allowance are rejected, stale
  snapshots still fail closed, and invalid `max_age` fails closed.
- The cflib capability probe no longer calls `Param.get_value()` inside the
  deadline loop; cflib source shows that `get_value()` may block up to 60 s
  while parameters initialize. The probe now waits on parameter initialization
  and reads `cf.param.values` under a monotonic timeout.
- Capability priority remains:
  1. reliable live ROS runtime parameter values;
  2. fresh verified cflib snapshot;
  3. unknown.

Expected current cf231 capability remains:

```text

Z = PASS
source = cflib_firmware_parameter_probe or reliable ROS runtime values
```

Flow Deck V2 handling remains explicit: `bcFlow2=1` and `bcZRanger2=1` together
are normal for Flow Deck V2 because the firmware initializes the integrated
VL53L1 ToF through the `bcZRanger2` driver.

### Estimator / Flight Readiness

Implementation PASS; live hardware readiness remains BLOCKED until real telemetry
and mission-origin conditions pass.

- Bridge preflight now blocks when Z positioning is missing, not only XY
  positioning.
- Pose stability now evaluates the full observation window using sample count,
  duration, max sample gap, XY span, Z span and standard-deviation diagnostics.
  The old first-sample to last-sample loophole is covered by a drift-out-and-
  return regression test.
- `/cf231/status` now preserves `supervisor_info_raw` and decodes firmware-
  documented bits through deck fault: can be armed, armed, can fly, flying,
  tumbled, locked, crashed, high-level control active/finished/disabled and deck
  fault. Unsafe supervisor states produce specific blocking codes.
- `/cf231/odom` velocity is used for static preflight settling. Thresholds are
  DMP safety policy values in config, not claimed firmware standards.
- Down-range and Kalman variance readiness are separated from deck capability.
  If live range or estimator variance telemetry is missing or stale, readiness
  blocks with `range_unavailable` / `estimator_not_converged` rather than
  inferring health from `bcZRanger2=1`.
- Flow/current-pose origins are bound to a hardware session id. Disconnect,
  reconnect or Bridge restart invalidates old origins; preflight blocks with
  `frame_origin_stale` or `frame_session_mismatch` until a current-session
  origin is captured.
- Planner-side preflight no longer duplicates live hardware readiness rules such
  as pose rate or XY positioning. Bridge is the hardware readiness authority;
  Planner retains mission/static/profile/route validation and renders Bridge
  preflight results.
- Pose-rate policy is now split into nominal `10 Hz` and minimum acceptable
  `8 Hz` default. The minimum is configurable and allows normal Crazyswarm2
  scheduling/transport margin, including observed `~9.3 Hz`, without weakening
  other readiness checks.
