**`flying/tumbled/locked/crashed/deck_fault` 全 false**。
→ **不是机体坏了，是 Flow Deck 这一个子系统没起来。**

### 3.2 关键对照：与 09-22 的"冻结"是**不同故障**

| 项 | 现在 | 2026-09-22 冻结期 |

- 09-22：**检测到了** deck，但光流数据冻结（驱动在跑，芯片无输出）→ 重新插接修好；
- 现在：**deck 根本没被检测到** → 故障在**更早的发现/上电初始化阶段**。

**所以 09-22"重新插接就好"的经验不一定适用。**

## 4. 待办：按顺序做（必须由用户物理操作）

### 步骤 1：充满电
当前 3.959 V / 70%，**充电电流只有 ~0.04 A，偏慢**。留意是否卡住；
若长时间不涨，怀疑电池/插头接触。

### 步骤 2：软件电源循环（**不用拆机，先做这个**）
cflib 的 `PowerSwitch.stm_power_cycle()` 可**通过电台重启 STM32 + 扩展板**
（源码注释：`Expansion decks will also be rebooted.`），这是**非飞行命令、不写 NVM**。

```bash
wsl -d Ubuntu
cd "/mnt/d/Deepseek WorkSpace"
# 只诊断
bash _dsh_scratch/run_probe.sh 3-1 deck_recover.py --sample-s 3
# 真正电源循环
bash _dsh_scratch/run_probe.sh 3-1 deck_recover.py --power-cycle --confirm-power-cycle
# 或直接抓新的启动横幅（看固件这次有没有发现 deck）
bash _dsh_scratch/run_probe.sh 3-1 boot_banner.py --power-cycle --confirm-power-cycle
```

判读：
- **恢复** → 是"开机初始化一次性失败"（供电/时序）→ 充满电再循环一次，然后走 §5；
- **仍全 0** → 更可能是物理接触/硬件 → 走步骤 3。

### 步骤 3：断电，重新压紧 Flow Deck
拔下 deck 重新压紧再上电。**建议在重插前后各测一次**，以确认到底是哪一步修好的。
