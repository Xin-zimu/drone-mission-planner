## 1. 总体方向

当前项目已经是比较完整的“离线规划与仿真演示平台”，但距离“可用于真实任务准备”还缺几块关键能力。

下一版不建议继续单纯增加面板，应优先补齐：

- **规划真实性**：让时间、地理坐标、空间约束和机队资源真正参与规划。
- **数据闭环**：让导入、规划、仿真与导出能够使用一致且可验证的数据。

建议将下一阶段定义为 **v1.2「真实任务规划基础」**。

## 2. 功能缺口优先级

| 优先级 | 建议迭代方向 | 当前缺口 | 后续计划 |
|---|---|---|---|
| P0 | 真实地理坐标 | 当前全部是本地米制坐标，QGC/WPL 明确不可直接飞 | 支持 WGS84/EPSG、经纬度与本地 ENU 转换、GeoTIFF/DEM、地理围栏和可执行航线导出 |
| P0 | 完整任务调度 | `earliest_start` 目前没有参与规划；deadline 只按当前航段时间评分，没有累计到达时间、任务执行时间和等待时间 | 支持时间窗、任务前置关系、累计 ETA 和甘特图 |
| P0 | 全局多机优化 | 当前是贪心分配，容易得到局部最优；多搜索区域还会限制无人机跨区域复用 | 使用已经声明但尚未使用的 OR-Tools，推进异构机队 VRP、时间窗和多架次调度 |
| P1 | 更可靠的协同避碰 | 当前主要是预约表加优先级等待，首航段冲突、迎头冲突、窄通道和死锁处理较弱 | 引入 Cooperative A*/CBS、垂直分层、通道锁和局部避障 |
| P1 | 真正的三维规划 | 当前仍是二维 A*，高度是航点赋值与事后风险校验，不能通过“升高绕过低障碍”等方式联合优化 | 增加分层图或稀疏 3D 搜索，并纳入爬升率和高度空域 |
| P1 | 更真实的仿真模型 | 目前风场基本为全局常量，飞行动力学较简化 | 加入加速度、转弯半径、阵风随时间变化、通信遮挡、传感器视场、GNSS 误差和链路延迟 |
| P2 | 多架次与补能 | 缺少返航充电、换电、载荷装卸、再次出动，以及任务中途补给 | 建立面向长时间任务的多架次与补给流程 |
| P2 | 场景比较与决策支持 | 缺少多个方案的对比和决策解释 | 增加多个规划方案并排比较、参数敏感性分析、Monte Carlo 故障仿真，以及“为什么方案 A 优于 B”的解释 |

## 3. 优先处理任务调度的依据

原建议指出两个关键问题：

1. 任务模型虽然已有 `earliest_start`，但规划模块没有使用。

- [任务分配 assignment.py](../src/drone_mission_planner/planning/assignment.py)：deadline 评分与任务分配逻辑。

### 8.2 对原始缺口描述的实施澄清

- 项目已有三维航点、三维视图和部分升降/停留仿真；目标是统一数据与联合三维搜索，不能重复开发一套仅用于显示的三维模型。
- `execution_duration` 已在部分航点停留与能耗计算中使用；缺口是统一累计调度，不是所有模块都完全忽略执行时间。
- `SearchArea.holes` 与部分带洞覆盖能力已经存在；要补的是标准空间数据导入、拓扑保真和完整端到端使用。
- QGC/WPL 已有文件输出；新增重点是地理坐标、高度语义、目标能力核验和执行证据。
- 当前软件版本 `1.1.0` 与项目文件格式 `1.6` 是两套版本号。产品 v1.2 不应把项目格式倒退写成 1.2。
- 多区域连续执行与充电后再次出动分别验收。前者在全局分配阶段完成，完整补能多架次在 P2 阶段完成。

### 8.3 范围分层

| 层次 | 内容 | 建议交付 |
|---|---|---|
| 数据与调度基础 | 航点统一、累计时间、前置依赖、全局分配 | v1.2 预览版 |
| 地理任务准备 | 坐标、DEM、空间导入、围栏、目标导出验证 | v1.2 完整版 |
| 空间与仿真增强 | 更强避碰、三维搜索、动态环境与传感器 | 后续 P1 阶段 |
| 长时任务与决策 | 多架次、补能、方案比较与 Monte Carlo | 后续 P2 阶段 |

版本名称是排期建议，不能用于跳过依赖。演示版可以停在前三项，真实任务准备版必须通过地理与导出验证门槛。

### 8.4 通用数据约定

| 数据 | 约定 |
|---|---|
| 距离 | 内部局部规划统一米；地理输入显式转换 |
| 时间 | 内部以任务开始为零点的秒数；可另存 UTC 起始时刻用于显示 |
| 高度 | 数值必须携带基准，不混用 AGL、海拔、椭球高和相对 home 高度 |
| 能量 | 真实模式采用明确物理单位；历史归一化值使用兼容层 |
| ID | 任务、无人机、路线、来源数据使用稳定 ID；名称不作为主键 |
| 计划 | 记录输入版本、算法版本、配置和生成时刻 |
| 实际执行 | 独立记录事件与实际时间，不覆盖原始计划 |
| 未知值 | 未知、无效、不适用与零分开表达 |
| 随机性 | 所有随机模型接受显式种子 |
| 输出状态 | 区分可行、部分可行、不可行、超时未知、取消和内部错误 |

### 8.5 通用执行规则

- 修改输入会使受影响的时间表、风险评估、缓存和导出验证失效。
- 规划和导入在快照上执行，成功后通过 `ProjectService` 一次应用。
- 用户取消或发生异常时，项目保持原状态。
- 后台结果提交前比较输入版本，过期结果不覆盖新编辑。
- 硬约束失败不能用较低风险分数或较短距离抵消。
- 新项目格式必须有历史版本迁移，不在加载时自动覆盖源文件。
- 一次实施一个阶段；每阶段保留应用启动、旧项目加载、保存和现有示例的基本可用性。

## 9. 统一航点数据模型详细计划

### 9.1 问题与目标

`planned_path` 和 `waypoints` 当前共同表示路线。路线编辑、覆盖规划、导入、仿真重规划和清空动作需要反复同步，容易出现地图显示、任务关联和实际仿真不同步。

目标是让 `waypoints` 成为唯一权威路线，二维路径仅由航点投影生成。A* 内部仍可以使用二维节点，但这些节点只是计算过程数据。

### 9.2 用户可见行为

- 修改航点高度、速度、动作、停留或位置后，地图、三维视图、时间表和风险状态同步更新。
- 删除任务相关航点时，明确处理任务是否仍被分配。
- 撤销一次路线编辑，恢复该路线及其任务关联，而不是只恢复一张表格。
- 保存并重新打开项目，任务 ID、动作、速度和高度模式不丢失。
- 旧项目加载时出现数据冲突，显示差异与迁移说明。

### 9.3 建议的数据结构

| 对象 | 核心字段 | 约束 |
|---|---|---|
| `Waypoint` | 稳定 ID、x、y、高度、高度模式、速度、动作、停留、task_id | 坐标有限；速度和停留合法；任务引用有效 |
| `RoutePlan`，建议新增 | ID、drone_id、revision、waypoints | 一条路线只有一个权威航点容器 |
| `RouteChange`，建议新增 | 修改原因、受影响任务、旧/新 revision | 用于失效传播、撤销和报告 |
| 二维路径投影 | `Point(x, y)` 序列 | 只读派生，不单独持久化 |

可先维持现有 `Drone.waypoints`，待调用方收敛后再抽取 `RoutePlan`。不能同时长期保留两个“权威”航点容器。

### 9.4 写入口收敛

| 入口 | 目标行为 |
|---|---|
| 单机路径规划 | 返回完整航点结果，服务层替换路线 |
| 全机任务分配 | 同一事务应用全部路线和任务关系 |
| 覆盖规划 | 保留区域、条带和扫描动作语义后拼接 |
| 航点表编辑 | 调用统一编辑方法，递增路线版本 |
| 地图拖动 | 修改对应航点/任务并使计划失效 |
| 航线导入 | 建立独立路线对象，经核验后应用 |
| 故障重规划 | 仅替换未来未执行部分，保留实际历史 |
| 清空路线 | 清除路线及相关分配/时间表，不留下悬空引用 |
| 撤销/重做 | 恢复完整事务快照 |

建议服务接口为 `replace_route`、`edit_waypoint`、`remove_waypoint`、`clear_route`，最终名称按项目现有风格统一。

### 9.5 迁移和冲突策略

| 旧项目情况 | 处理 |
|---|---|
| 只有二维路径 | 按旧规则生成航点，标记默认高度/动作来源并要求重新核验 |
| 只有有效航点 | 保留全部语义 |
| 两种表示一致 | 采用航点，后续保存不再写二维副本 |
| 几何不一致 | 生成冲突摘要，保留原文件；用户选择/修复前不能用于执行导出 |
| 无效坐标或悬空任务 ID | 明确错误位置，不静默置零或丢弃 |
| 未知未来格式 | 拒绝按当前格式编辑，提示版本信息 |

建议单独升级文件格式，例如 2.0；具体编号在阶段开始时确认。历史 1.0～1.6 先经现有迁移链规范化，再进入新迁移。迁移备份、原子保存和恢复也使用同一序列化规则。

### 9.7 验收案例

1. 同一位置有“到达、拍照、悬停”三个语义不同的航点，保存后不被合并。
2. 删除服务点后任务不能继续显示为已安排服务。
3. 修改高度后二维位置不变，三维视图和净空校验更新。
4. 故障重规划保留已完成动作，不重复拍照/服务。
5. 旧项目两种路线冲突时显示具体无人机及差异。
6. 搜索业务代码不再发现可写的持久化 `planned_path`，历史迁移代码除外。

## 10. 完整任务调度详细计划

### 10.1 首版能力

支持最早服务开始、完成截止、执行时长、前置依赖、累计 ETA、等待、返航，以及故障后的现场续算。先让现有贪心分配使用正确规则，再接优化器。

### 10.2 时间定义

| 字段 | 定义 | 合法性 |
|---|---|---|
| `earliest_start` | 允许开始任务服务的最早时刻 | 空表示无额外下界；否则非负有限数 |
| `deadline` | 完成服务的最晚时刻 | 空表示无上界；否则不早于可行下界 |
| `deadline_policy`，建议新增 | hard / soft / legacy_soft | 新任务默认 hard，旧评分语义显式迁移 |
| `execution_duration` | 服务持续时长 | 非负，零时长任务合法 |
| `arrival_time` | 到达指定位置及执行高度 | 由实际航段模型计算 |
| `start_time` | 条件满足后开始服务 | 不早于到达、时间下界和前置完成 |
| `finish_time` | 服务完成 | 开始 + 服务时长 |
| `departure_time` | 离开该任务位置 | 完成 + 显式离场等待 |
| `wait_reason` | 时间窗、前置、冲突、资源等 | 允许多个原因但不能重复计时 |

硬截止超时会使方案不可行；软截止允许迟到但必须显示秒数和代价。历史 deadline 不能未经说明从“评分项”变成已验证硬约束。

### 10.3 累计计算

设上一段离开时间为 D，当前航段时间为 T，最早开始为 E，前置任务允许的最早时刻为 P，服务时长为 S：

```text
arrival = D + T
start = max(arrival, E, P)
wait = start - arrival
finish = start + S
departure = finish + explicit_post_service_hold
hard_deadline_passed = finish <= deadline
```

无前置/无下界不增加限制。第一次规划 D 从任务原点开始，重规划 D 从当前任务时钟开始。

航段时间必须匹配仿真采用的水平/垂直运动方式：同时升降和平移与先升降再平移的结果不同，不能分别由规划器和仿真器各算一套。

### 10.4 固定数值案例

| 项目 | A | B |
|---|---:|---:|
| 从上一位置航行 | 30 s | 20 s |
| 最早开始 | 60 s | 120 s |
| 服务时长 | 40 s | 30 s |
| 完成截止 | 110 s | 140 s |
| 前置任务 | 无 | A |

预期：A 在 30 s 到达、等待 30 s、60 s 开始、100 s 完成；B 在 120 s 到达、150 s 完成。B 硬截止失败，软截止迟到 10 s。不能以 B 的单段旅行时间 20 s 得出符合 deadline 的结论。

### 10.5 任务依赖

首版采用“全部前置完成后开始”的关系：

- `predecessor_ids`：稳定任务 ID 列表。
- 可选最小间隔 `min_lag_seconds`：前置完成后额外等待。
- 同机执行要求是独立字段，不与普通依赖混淆。
- 校验不存在的任务、自引用、重复依赖和环路。
- 错误展示具体环路，如 `A → C → B → A`。
- 前置被取消、失败时，后继进入阻塞状态，不能自动视为满足。
- 执行中任务定义可否中断；不可中断任务锁定剩余服务区间。
- 已完成前置使用实际完成时间；跨机依赖必须协调全局时间线。

### 10.6 等待和能源

| 等待位置 | 时间计入 | 能源计入 | 空间检查 |
|---|---|---|---|
| 基地地面 | 起飞前等待 | 地面待机，不能套用悬停功率 | 基地容量/占用 |
| 空中等待点 | 到达后等待 | 悬停功率 | 围栏、净空、机间距离 |
| 任务执行位置 | 时间窗/前置等待 | 等待与服务分别记账 | 持续占用 |
| 通道入口 | 冲突让行等待 | 按所在状态消耗 | 不能堵住已占用通道 |

空中等待不可行时尝试延迟起飞或改等候点，不能直接在禁飞区悬停。增加等待后必须重新计算后续 deadline、能源和返航。

真实模式统一能量单位：若采用 W、s、Wh，则能量为 `功率 × 秒数 / 3600`。历史归一化电量不直接改名为 Wh。安全储备是可行性约束，不在每段重复扣除。

### 10.7 仿真状态和事件

建议表达业务状态：未分配、已安排、航行中、等待中、服务中、已完成、失败、取消、依赖阻塞。现有枚举如何兼容由领域层决定。

事件至少包括：到达、等待开始/结束、服务开始/完成、依赖解除、硬截止违约、任务取消、重规划应用。每个事件带任务 ID、无人机 ID、逻辑时刻、方案版本和原因。

仿真触发服务前再次核对时间窗与前置。运行时违约记录实际事实，不能为保持报表漂亮而篡改为计划时间。

### 10.8 甘特图与交互

- 每机一行；起飞、航行、等待、服务、返航用不同区间表达。
- 服务块显示名称、计划开始/完成、截止和迟到秒数。
- 悬停查看等待原因、前置任务、能源与路线 ID。
- 点击任务块定位地图与属性面板。
- 支持按无人机、任务状态、超期和阻塞筛选。
- 计划与实际分开展示，保留当前逻辑时刻线。
- 首版只读甘特；拖拽调整排程作为后续交互，不新增隐式写入口。

## 11. 全局多机优化详细计划

### 11.1 目标

联合决定“任务由谁做、按什么顺序做、什么时候做”，在同一组约束和目标下改善贪心结果，并允许同机跨多个搜索区域连续执行。

OR-Tools 的 VRPTW 模型可作为基础时间窗路由实现参考；本项目的任务服务、能源和跨机依赖需要额外明确建模，不能直接照搬示例认定全部支持。参考资料见第 24 章 R1。

### 11.2 首版约束矩阵

| 约束 | 首版处理 | 不满足时 |
|---|---|---|
| 机体状态 | 排除故障、不可出动机体 | 给出拒绝原因 |
| 起终点 | 每机真实起点与指定合法结束基地 | 不以统一虚拟基地代替 |
| 能力/载荷 | 匹配设备、载重与任务类型 | 禁止不匹配分配 |
| 时间窗 | 累计服务开始/完成 | 硬失败或软迟到 |
| 前置依赖 | 显式全局约束 | 不支持的关系阻断该求解模式 |
| 能源 | 整条路线、服务、等待、返航、储备 | 修复或拒绝 |
| 不可达航段 | 禁止该边 | 不能用直线代替 |
| 必做任务 | 不允许静默丢弃 | 整体失败或明确部分方案 |
| 可选任务 | 可按优先级与惩罚不分配 | 列出未分配原因 |
| 已执行/已锁定任务 | 固定历史或剩余区间 | 不重复分配 |

取送任务的动态载荷是独立能力。如果首版只支持设备携带要求，应明确限制，不能把恒定载荷检查标为完整配送容量模型。

### 11.3 求解器分层

建议接口：

```text
AssignmentSolver.solve(snapshot, context, settings)
TravelCostProvider.get(drone_profile, origin, destination, environment_revision)
ScheduleEvaluator.evaluate(candidate, context)
PlanValidator.validate(candidate, snapshot)
```

- Routing 适配器负责基础车辆路径和时间维度。
- 复杂资源调度、共享基地、多架次和某些跨机约束，先评估 CP-SAT 或分解模型。
- 输入包含求解器不支持的硬约束时，返回能力不足，不忽略字段。
- 最终候选必须经过独立调度、能源和空间核验器。
- 内部错误、无解、超时未知和用户取消分别返回。

### 11.4 航段代价计算

矩阵元素应包含可达性、实际安全路径、距离、飞行时间、能源和版本信息。

不同机型的安全半径、速度、爬升率、载荷和风响应不同，不能未经区分共用代价矩阵。风可能造成有向代价，A→B 与 B→A 不一定相同。

工作步骤：

1. 确定机队能力分组，避免为等价机型重复搜索。
2. 使用当前安全规划器产生候选航段。
3. 计算机型相关时间和能源。
4. 缓存代价，Key 包含全部相关环境/配置版本。
5. 求解后根据真实选中路径复算全程。

### 11.5 时间与整数刻度

- 业务层保留明确秒数，优化器采用固定整数刻度，例如 0.1 s。
- 旅行、服务、最早开始向保守方向取整；完成截止不因舍入被放宽。
- 如果时间维度表示服务开始，则上界需要按 `deadline - execution_duration` 转换。
- 服务只在一个位置计入，例如离开节点的 transit。
- 等待 slack 和规划 horizon 必须有合理上界。
- 检查惩罚系数和大常数的整数范围，避免溢出或失去优先级。

### 11.6 优化目标

建议按以下优先级比较方案：

1. 硬约束全部满足。
2. 必做任务完成。
3. 最大化可选任务优先级收益。
4. 最小化软截止迟到。
5. 最小化所有无人机最晚完成时刻。
6. 最小化总能源和总距离。
7. 在前面目标等价时改善负载均衡与结果稳定性。

UI 显示每项指标和单位。如采用加权目标，必须确定各项归一化和范围，不能让节省 1 m 路程抵消必做任务遗漏。

### 11.7 跨区域复用

- 将区域拆成覆盖块，每块含入口、出口、允许方向、完整扫描轨迹、时长和覆盖收益。
- 扫描方向的入口与出口必须成对选择，不能组合出不存在的扫描块。
- 点任务、区域块、转场和返航进入统一任务序列。
- 同一机可以连续执行区域 A、B，累计时间和能量必须满足。
- 清除当前“每机只接收一个区域结果”的应用限制。
- 任务覆盖率来自实际覆盖单元，不以分配状态代替完成度。
- 优化结论限定在给定分块模型内，不宣称对任意覆盖形状证明全局最优。

### 11.8 冲突后修复

```text
联合分配 → 时间表 → 航线 → 冲突调整
                          ↓
        重算时窗 / 依赖 / 能源 / 返航
                          ↓
       通过则应用；失败则修复或重新求解
```

设置总时间预算和最大修复轮次，记录每次拒绝原因。静态能源模型无法充分表达等待时，可采用明确保守上界并在后处理中复算；失败不能作为成功结果保存。

### 11.9 UI 与降级

- 提供“贪心基线”和“全局优化”选项、求解时间预算和目标偏好。
- 显示矩阵构建、求解、核验阶段，均可取消。
- 同预算比较经过同样核验的基线与优化候选，保留更优者。
- 时限内有解：显示可行但未证明最优。
- 时限内无解：显示未找到可行解，不能冒充不可行证明。
- OR-Tools 缺失：显示优化不可用，可继续使用已标识的基线模式。
- 不自动覆盖用户保存的其他候选方案。

## 12. 真实地理坐标详细计划

### 12.1 目标与用户流程

保留本地演示项目，同时增加明确地理参考的项目模式。

用户流程：选择地理模式 → 配置项目原点和坐标系 → 确认高度来源 → 导入/校准空间数据 → 预览范围与控制点 → 保存地理配置 → 进行米制规划 → 输出真实经纬度。

地理设置需要展示当前模式、原点、水平 CRS、垂直基准、轴方向、有效范围和数据精度。配置缺失时显示具体缺项。

### 12.2 坐标层次

| 层次 | 约定 | 用途 |
|---|---|---|
| 原始数据 | 保留源 CRS、单位、轴顺序和来源 | 追溯、重新导入 |
| WGS84 地理参考 | 经度、纬度、明确基准的高度 | 地理交换与外部显示 |
| ECEF 中间层 | 地心三维坐标 | 必要时用于严格 ENU 变换 |
| 本地 ENU | x 东、y 北、z 上，单位米 | 距离、规划与局部几何 |
| Qt 屏幕坐标 | y 通常向下 | 显示与鼠标操作，显式转换 |

建议采用经验证的 CRS 库与 topocentric 转换，不使用简单经纬度乘固定系数作为通用 ENU 实现。转换技术参考见第 24 章 R2。

### 12.3 GeoReference 建议字段

| 字段 | 内容 |
|---|---|
| `mode` | local_only / georeferenced |
| `horizontal_crs` | 标识及可复现定义 |
| `origin_longitude` / `origin_latitude` | ENU 原点 |
| `origin_ellipsoid_height` | 建立三维原点需要的椭球高 |
| `vertical_datum` | 源高度基准或 unknown |
| `local_axis_convention` | ENU 与历史画布方向的关系 |
| `validated_extent` | 已验证适用范围 |
| `source_accuracy` | 数据或控制点精度，不等于数值换算精度 |
| `calibration_points` | 控制点与独立检查点 |
| `transform_version` | 转换配置和所用网格版本 |

### 12.4 两类地理操作

**本地项目地理校准：** 为既有米制几何确定真实原点、方向、比例和高度。所有数据在预览中叠加，显示控制点残差；不能把旧 x/y 直接当作经纬度。

**更换原点并保持真实位置：** 先按旧基准取得真实位置，再变换为新 ENU；同步变换任务、基地、路线、区域、障碍和资源定位。完成后全部相关规划/导出验证失效。

这两类操作在 UI 中使用不同名称。用户改变原点时必须看到对象真实位置是否会改变。

### 12.5 高度基准

必须区分四种常见语义：

- 椭球高：相对参考椭球。
- 海拔/正高：相对具体垂直基准。
- AGL：相对该位置地形。
- 相对 home：相对起飞参考点，不等于相对沿途地形。

处理规则：

1. 字段叫 `MSL` 不能代替实际基准确认。
2. AGL 换成固定海拔航点时，沿完整航段检查地形，不只看端点。
3. 缺少高度转换网格、DEM 或基准未知时，返回不可验证状态。
4. 起飞点高度变化使相对高度任务文件失效。
5. 在净空中加入源分辨率、垂直误差和定位裕度。
6. 精确转换测试与数据实际精度分开报告。

### 12.6 地理围栏

建议统一允许区、排除区和限高体积：

| 内容 | 规格 |
|---|---|
| 平面边界 | Polygon/MultiPolygon 和内环 |
| 类型 | 允许区、禁止区、受限高度区 |
| 垂直范围 | 下界/上界及其高度基准 |
| 时间范围 | 可选生效区间；不支持时明确拒绝该严格场景 |
| 来源 | 数据来源、时间、精度和备注 |
| 安全缓冲 | 机体半径、定位/数据误差，单位明确 |

校验包含起点、起降、整条航段、等待和返航。点都合法但连线越界的路线仍然失败。允许区的洞作为非允许区域参与核验。

### 13.2 GeoJSON / KML 功能矩阵

| 几何 | 目标处理 | 关键要求 |

| MultiLineString | 逐部件处理 | 保留分组 |
| GeometryCollection | 按明确支持列表导入 | 不支持成员列入报告 |
| KML 多几何/内环 | 规范化到共同中间模型 | 保留高度模式 |

标准地理输入与历史本地米制模式分开。GeoJSON 标准语义参考第 24 章 R3；不能仅因为数据格式同为 JSON 就沿用本地坐标解释。

### 13.3 属性和引用映射

### 13.4 拓扑检查

| 检查项 | 发现问题后的行为 |
|---|---|
| 自相交 | 标注相交位置，拒绝默认作为有效区域 |
| 外环未闭合 | 可提供闭合预览，应用后记录修复 |
| 点数不足/零面积 | 报错 |
| 洞越出外环 | 标注洞 ID 与越界位置 |

## 15. 协同避碰详细计划

### 15.1 目标与实施顺序

先明确当前预约与优先等待算法的边界，再逐步加入空间—时间搜索、通道锁和小规模 CBS。规划期避碰与运行时局部避障分别实现，最终使用同一套安全间隔定义。

| 子阶段 | 交付 | 前置 |
|---|---|---|
| C1 | 完整冲突检测和边界回归 | 统一航点、时间线 |
| C2 | Cooperative A* 与有界优先级重排 | C1 |
| C3 | 通道锁、入口等候和死锁处置 | C2 |
| C4 | 小规模 CBS/有界次优探索 | C1、明确离散模型 |
| C5 | 垂直分层与局部避障 | 三维规划、运动模型 |

### 15.2 冲突类型

| 冲突 | 例子 | 必须检查 |
|---|---|---|
| 首航段 | 两机起飞后立即交叉 | 不能从第二段才开始预约 |
| 同位置 | 两机同一时刻经过交点 | 安全半径和时间容差 |
| 迎头交换 | 相向穿越同一窄边 | 边占用，不能只查节点 |
| 追尾 | 后机快于前机 | 连续接近距离 |
| 对角穿越 | 两条对角线在格内相交 | 格内几何交叉 |
| 等待冲突 | 让行机悬停在另一机路径上 | 整个等待区间占用 |
| 终点驻留 | 第一机到达后未离开 | 终点后续占用，不能瞬间消失 |
| 起降资源 | 同基地同一时刻起飞/降落 | 平面、高度与资源时间 |
| 垂直交换 | 两机同时切换高度层 | 升降全程安全间隔 |
| 故障占道 | 故障机停在通道内 | 当前状态和封锁更新 |

### 15.3 冲突数据与报告

建议 `Conflict` 字段包括 ID、两机 ID、类型、起止时间、最近距离、阈值、位置/航段、解决状态和已采用动作。

报告区分“发现冲突”“已处理并复核”“未解决”“因输入改变失效”。地图标注位置，时间轴标注区间，点击可查看涉及路线。

### 15.4 连续时间复核

对于同一时间区间内匀速线性运动，设相对位置 r、相对速度 v、区间长度 Δt：

```text
t_closest = clamp(-dot(r, v) / dot(v, v), 0, Δt)
d_closest = norm(r + v * t_closest)
```

v 为零时直接检查固定距离。此公式仅用于满足假设的分段；存在转弯或加速度时需分段、保守包络或带误差界的自适应采样，不能套用后声称全程安全。

每机安全尺寸、定位不确定度、跟踪误差和时间偏差形成间隔预算。上下分层时使用明确的水平/垂直分离规则。

### 15.5 Cooperative A* 与预约

- 节点含空间位置和时间，动作包括移动和合法等待。
- 节点占用、边占用、对角交叉和终点驻留进入预约。
- 不同机速用一致的时间区间表达，不能默认每机一格一秒。
- 规划窗口、最长等待和最大优先级重排次数可配置。
- 不能一直让低优先级机等待；加入等待老化或有限重排策略。
- 时间搜索失败返回具体冲突范围，不无限扩展时间。

优先级预约法不保证所有可行实例都能找到解；失败应区分“该策略未解决”与“已证明无解”。

### 15.6 通道锁与死锁

建议 `CorridorReservation` 包含通道 ID、方向、占用机组、进入/退出时刻、等候区和状态。

- 通道入口必须有合法等候空间。
- 已进入机体未确认离开前，不能仅因预计时间到期就放行相向机。
- 故障后重新判断通道是否可用，锁到期不代表障碍消失。
- 待资源关系形成等待图，检测循环等待和长期无进展。
- 处置顺序可为重新排序、入口延迟、合法退让点、局部重规划。
- 无安全恢复动作时终止相关任务并报告，不为打破死锁强制穿越。

### 15.7 CBS 的边界

CBS 是高层冲突约束搜索与低层单机路径搜索结合的候选方法，参考第 24 章 R6。引入前固定：状态离散方式、允许动作、冲突定义、目标函数与终点驻留规则。

首版只针对小规模明确模型验证，不把标准离散 CBS 的最优性直接推广到带动力学、连续时间和能源的完整系统。

设置搜索节点与耗时预算；达到预算可返回已有核验候选或明确失败。任何近似/有界次优模式记录名称与参数。

### 15.8 与任务调度闭环

每次避碰插入等待、改变路径或调整高度后：

1. 重算旅行时间与任务开始/完成。
2. 重算能源、返航与安全储备。
3. 校验依赖和硬截止。
4. 重新检查所有受影响机组的空间冲突。
5. 通过后一次应用；否则修复或返回未解决。

### 15.9 实施任务与验收

- [ ] COL-02：补首段、迎头、对角、驻留和追尾检测。
- [ ] COL-03：实现空间—时间预约与合法等待。
- [ ] COL-04：实现优先级重排和饥饿限制。
- [ ] COL-05：实现通道识别、锁与故障处理。
- [ ] COL-06：实现死锁检测与有界恢复。
- [ ] COL-07：小规模 CBS 原型和独立实例对照。
- [ ] COL-08：地图/时间轴报告及调度复核闭环。

验收必须包含两机交叉、相向窄通道、三机循环等待、同基地起飞、快速追尾、长时间悬停和故障占道。全部成功场景经独立连续航段复核；失败场景有原因和有限返回时间。

主要模块：`planning/deconfliction.py`、`planning/collision.py`、`simulation/engine.py`；建议新增预约/通道资源模块。

## 16. 三维规划详细计划

### 16.1 目标

让路径搜索主动选择高度，通过合法升降绕过低障碍，并同时满足地形、空域、爬升率与能源要求。已有三维视图和航点高度继续复用。

### 16.2 首版采用分层图

- 状态为 `(x, y, altitude_layer)`；如动作可行性还依赖航向，再显式扩展状态。
- 高度层来源于配置范围、地形净空和任务目标高度。
- 支持水平、爬升、下降和明确允许的斜向边。
- 边在完整三维空间核验，禁止仅检查端点。
- 任意高度起终点通过合法连接边接入图，不能直接四舍五入后改变任务位置。
- 同一地图内高度层基准一致；AGL 数据先按可验证地形解释。

### 16.3 约束

| 约束 | 处理 |
|---|---|
| 地形净空 | 全航段高于地形 + 安全余量 |
| 障碍体积 | 水平形状和高度共同检查 |
| 空域上下界 | 不能通过升高越过无限高或上界未知的禁飞区域 |
| 爬升/下降率 | 高差决定最低转换时间 |
| 机型能力 | 多旋翼与固定翼能力分开 |
| 能源 | 升降、水平和等待统一计算 |
| 任务执行高度 | 到达条件包含高度，不只含 x/y |
| 多机分离 | 高度调整后重新检查机间冲突 |

### 16.4 代价与启发式

建议首先优化可行性与时间，再考虑能源和高度变化偏好。各代价非负、单位明确。

A* 启发式使用不会高估的下界；如采用加权启发式以换取速度，标记为近似搜索。爬升绕过障碍可能更快但更耗能，应在结果中分别展示，不能把几何最短自动叫综合最优。

### 16.5 轨迹后处理

1. 合并仅在几何和动作语义上冗余的点。
2. 平滑前后分别计算路径与能源。
3. 平滑不得穿过地形或障碍。
4. 保留任务点、动作点、起降点及必须遵守的高度转换。
5. 检查斜段是否超过爬升率。
6. 固定翼若未实现转弯半径和航向连续性，明确不支持其可执行轨迹。

### 16.6 UI

- 规划设置中选择二维保守/分层三维模式。
- 设置最低/最高高度、层间距、净空与求解预算。
- 三维视图显示搜索结果、爬升/下降段和受限空间。
- 高度剖面叠加地形、净空、空域上下界。
- 对比二维绕行与三维绕障的距离、时间、能耗；不强制三维方案一定更优。

### 16.7 实施任务

- [ ] 3D-01：三维障碍、空域和高度基准规范化。
- [ ] 3D-02：高度层和合法邻接边生成。
- [ ] 3D-03：带时间/能源代价的搜索。
- [ ] 3D-04：任意高度起终点接入。
- [ ] 3D-05：平滑与全航段重新验证。
- [ ] 3D-06：接入分配代价和仿真时间模型。
- [ ] 3D-07：高度剖面、模式切换和解释。
- [ ] 3D-08：性能剖析后评估稀疏 3D/自适应层。

### 16.8 验收案例

- 低障碍：允许升高越过，升降时间和能量正确。
- 高障碍且有上限：水平绕行或拒绝，不越过空域。
- 山脊：两端安全但中段危险的直线被拒绝。
- 狭窄高度通道：只能在特定层通过。
- AGL 沿坡：爬升率不足时不能输出虚假贴地轨迹。
- 双机换层：升降阶段依然满足分离。
- 二维降级：只在通过相同安全校验时允许使用。

主要模块：`planning/astar.py`、`planning/grid.py`、`planning/route_planner.py`、`planning/altitude_validator.py`、`domain/terrain.py`；建议新增分层图实现。

## 17. 仿真真实性详细计划

### 17.1 分层模型与模式

保留快速确定性模式用于回归，增加可配置真实性等级。结果记录启用的模型、参数、版本和种子。

| 等级 | 内容 | 用途 |
|---|---|---|
| S0 | 现有确定性模型 | 快速规划检查 |
| S1 | 加速度、升降和转弯约束 | 运动可行性 |
| S2 | 时空风与能耗扰动 | 环境鲁棒性 |
| S3 | 通信遮挡、延迟和定位误差 | 协同与失联场景 |
| S4 | 传感器视场与观测质量 | 有效覆盖与任务成效 |

### 17.2 运动学

建议机型参数：最大速度、加速度、减速度、爬升/下降率、航向变化率、允许转弯半径和是否可悬停。

- 速度随时间积分，不能在航点处无过程从 0 跳到最大值。
- 接近悬停/降落点提前减速。
- 路径转角的速度受允许转弯能力影响。
- 起飞、爬升、巡航、转弯、服务、下降和降落有明确转换条件。
- 任务服务期间仍可能受到风和能耗影响。
- 规划器可调用同一运动耗时估计，或明确使用保守近似并给出误差。

### 17.3 时空风场

建议提供 `wind_at(position, altitude, mission_time)` 查询接口，先做可控模型：

1. 全局常量风，兼容原项目。
2. 随高度变化的风层。
3. 分区风场。
4. 随时间变化的风速/风向。
5. 接受种子的阵风过程。

参数使用 m/s、方向约定和逻辑时钟。阵风不依赖 UI 帧率；暂停不继续改变风。风速导致地速不足或超过控制能力时，触发明确状态/策略，不能产生负时间或瞬移。

### 17.4 能源真实性

- 分别计算水平、爬升、下降、悬停和载荷服务能量。
- 参数含来源和适用机型，未校准时标记研究/演示用途。
- 可逐步增加载荷、风、温度和电池健康度影响。
- 电池剩余不能无解释跳变，实际消耗与统计总量一致。
- 下降不默认回收能量；如建模回收必须有机型依据。
- 与任务规划的差异用于修正预估，不回写篡改历史计划。

### 17.5 通信遮挡与链路

| 能力 | 规格 |
|---|---|
| 距离连接 | 保留既有链路和多跳逻辑 |
| 地形/障碍遮挡 | 检查两节点之间视线与阻挡物 |
| 延迟 | 消息进入带发送/到达时刻的队列 |
| 丢包 | 由固定种子和配置模型决定 |
| 带宽 | 可限制单位时间可传输信息 |
| 链路状态 | 在线、弱链路、失联、恢复；防抖策略明确 |
| 故障策略 | 记录、等待、返航或重规划，分别说明触发条件 |

消息含序号和时间戳，处理迟到、乱序和过期消息。不能使用已失效状态替代当前状态而不说明。若引入实时同步模型，应与导出能力明确分开。

### 17.6 GNSS 与估计状态

将真值、传感器测量值和用于控制的估计值分开：

- 可配置固定偏差、随机噪声、短时失锁和恢复。
- x/y/z 误差可分别配置，不用单一距离噪声替代全部定位误差。
- 地图可切换显示真值/测量轨迹。
- 安全核验可使用不确定度裕度，报告实际最小距离。
- 相同种子复现相同误差过程；不同随机来源使用独立子种子。

### 17.7 传感器视场与覆盖

- 配置水平/垂直视场、朝向、姿态、安装方式、有效距离与采样频率。
- 最小实现可采用平地、垂直向下的视场投影；例如截面覆盖宽度为 `2 × AGL × tan(FOV / 2)`，必须标注该几何假设。
- 山地、倾斜和遮挡场景用射线与地形交会或明确保守近似。
- 区分“飞过某单元”“可见某单元”“得到满足质量要求的观测”。
- 拍照任务统计真实触发时刻和足迹，不能仅在到达任务点时增加计数。
- 扫描速度、采样频率和重叠率共同影响有效覆盖。

- [ ] SIM-02：加减速、转弯、起降状态转换。
- [ ] SIM-03：时空风场和固定种子阵风。
- [ ] SIM-04：分项能源、参数来源和误差报告。
- [ ] SIM-05：视线遮挡、消息队列、延迟和丢包。
- [ ] SIM-06：真值/测量/估计状态分离。
- [ ] SIM-07：视场、采样、遮挡和有效覆盖。
- [ ] SIM-08：模型等级、回放和计划/实际对比。

验收：不同播放倍率得到相同逻辑结果；加速度和转弯限制不被跳过；阵风、延迟和丢包能复现；链路恢复不重复触发事件；观测覆盖与飞行覆盖可不同且原因可解释。

## 18. 多架次与补能详细计划

### 18.1 目标与业务流程

支持一架无人机完成任务、返场、换电/充电、装卸、再次出动；同一任务规划周期内累计时间、能源和资源占用。

建议从固定基地、固定换电时长开始，再增加有限电池库存、共享充电站、装卸和中途补给。

### 18.2 数据模型

| 对象 | 字段 |
|---|---|
| `Sortie` | ID、drone_id、起终基地、路线、开始/结束时刻、能源 |
| `ServiceStation` | ID、位置、可服务机型、充电/换电/装卸工位与开放时间 |
| `BatteryPack` | ID、容量、健康度、剩余能量、所在位置、占用状态 |
| `TurnaroundOperation` | 机体、电池/工位、类型、开始/结束、前置条件 |
| `PayloadInventory` | 载荷类型、数量、位置、消耗/归还规则 |

机体、电池、充电口和载荷是不同资源，不能用一个“充电时间”字段隐含全部过程。

### 18.3 状态机

```text
待出动 → 起飞 → 执行 → 返航 → 降落
                               ↓
          等待工位 → 装卸/换电/充电 → 检查
                               ↓
                        下一架次待出动
```

每条状态转换有非零时长或明确零时长理由。未取得工位时排队，未取得电池时等待，能源不足以返航时不能凭补能计划忽略当前不可达问题。

### 18.4 约束

- 同一机体的架次互斥，前一架次落地并完成周转后才能出发。
- 同一电池同一时刻只能处于一个机体/充电位/库存位置。
- 充电或换电不能让其他正在使用的电池瞬间满电。
- 工位数量、开放时间和机型兼容参与排程。
- 任务时间窗跨架次连续计算，不能每次起飞重置。
- 飞行前确认所需载荷在该基地可用。
- 中途补给基地必须可达且合法，包含到站余量与备用方案。
- 返场、排队、周转和再次起飞都计入总完成时间。

### 18.5 排程算法路线

1. 单机固定换电时长、多架次状态机。
2. 多机共享换电工位和有限电池库存。
3. 充电曲线按确认的模型分段近似。
4. 路由与基地资源的联合/分解优化。
5. 中途补給与多基地再调度。

可以评估 CP-SAT 资源区间约束。若使用虚拟架次车辆，必须补上同一真实机体的时间和资源互斥，不能只复制无人机数量。

### 18.6 UI 与报告

- 基地面板显示工位、库存电池和载荷。
- 甘特图显示机体架次与基地资源两种视图。
- 展示等待、充电、换电、装卸和检查时间。
- 方案摘要显示架次数、补能次数、排队总时长和资源瓶颈。
- 故障机返场/停场后相应资源占用有明确释放或隔离规则。

- [ ] SORT-01：架次、站点、电池和周转对象。
- [ ] SORT-02：单机返航、换电、再次出动状态机。
- [ ] SORT-03：共享工位和有限库存排程。
- [ ] SORT-04：载荷装卸、耗用和位置变化。

## 19. 场景比较与决策支持详细计划

### 19.1 目标

允许保存并比较多个方案，理解目标权衡，探索参数变化和随机故障对任务结果的影响。

### 19.2 方案快照

每个候选保存：项目输入版本、机队/环境/任务配置、求解器与版本、种子、预算、完整路线、时间表、核验结果和指标。

编辑当前项目不修改历史候选。跨不同任务集合比较时显示差异，不能把“少做任务更快”解释为纯算法提升。

### 19.3 比较指标

| 维度 | 指标 |
|---|---|
| 任务 | 完成数量、必做完成率、优先级收益、未分配原因 |
| 时间 | 总完成时刻、迟到秒数、等待、服务和转场 |
| 能源 | 总消耗、最小返航余量、每项任务消耗 |
| 覆盖 | 有效覆盖、重复覆盖、未覆盖区域 |
| 机队 | 使用数量、负载差异、架次数 |
| 补能 | 充电/换电次数、排队、资源占用 |
| 协同 | 最小间隔、冲突处置次数、通信中断 |
| 计算 | 求解耗时、核验耗时、状态和近似 |

### 19.4 交互

- 选择两个或多个方案并排展示地图、甘特与指标。
- 地图缩放和当前时间可联动，使用相同显示范围。
- 以绝对差值和百分比展示变化；基线为零时不计算无定义百分比。
- 可按任务/无人机展开变化原因。
- 支持将一个候选应用为当前方案，操作进入撤销历史。
- 比较报告导出为 HTML/CSV，保留比较条件。

### 19.5 决策解释

解释由已计算事实生成，优先使用规则模板和结构化证据。例如：

> 示例文案：方案 B 增加一架无人机，最晚完成时间减少 180 s，但总能量增加 12%；任务 T07 从软截止迟到变为按时完成。

以上数字仅为文案示例，实际报告必须来自指标差值。解释要区分约束导致、求解偏好导致和环境假设导致，无法证明原因时标明观察而非因果结论。

### 19.6 参数敏感性

参数候选包括电池容量、风速、服务时长、任务窗、安全间隔、机队数量和故障时间。

- 固定基线，明确变动参数、范围和步长。
- 区分“沿用原计划重放”和“每个参数重新优化”，两者回答不同问题。
- 同时显示成功/失败和性能指标，不只绘制成功样本。
- 找出造成任务不可行的阈值区间；离散采样不能假装精确临界值。
- 批量计算可取消、保存进度和恢复。

### 19.7 Monte Carlo

- 设置样本量、种子策略、故障分布、风/定位/通信扰动范围。
- 每次样本保留输入扰动、结果、失败类型和关键事件。
- 比较方案采用配对种子或共同随机数，减少无关波动。
- 输出成功率、分位数、样本量和适当区间估计。
- 零失败只表示有限样本中未发现失败，不解释为绝对可靠。
- 区分随机不确定性和模型未校准带来的不确定性。
- 性能超预算时支持批次和提前停止，但报告说明停止规则。

- [ ] DEC-01：不可变候选快照和版本来源。
- [ ] DEC-02：统一指标与比较差值。
- [ ] DEC-03：地图/甘特并排和选中联动。
- [ ] DEC-04：规则解释和证据定位。
- [ ] DEC-05：参数扫描与计划重放/重优化区分。
- [ ] DEC-06：Monte Carlo 批次、种子、恢复和统计。

验收：同一方案对比差值为零；修改源项目不污染快照；参数变动可追溯；固定种子复现样本；失败样本不被过滤掉；解释数字与报告一致。
## 20. 工程优化详细计划

### 20.1 主窗口按业务抽取

拆分应随对应业务阶段进行，不先把整个主窗口机械拆成多个大文件。

| 建议控制器 | 职责 | 不承担的职责 | 抽取时机 |
|---|---|---|---|
| `PlanningController` | 规划入口、进度、取消、结果应用 | A*、VRP 和约束算法 | 航点/调度/全局分配阶段 |
| `SimulationController` | 播放、暂停、事件、现场重规划 | 物理积分算法本体 | 调度与仿真阶段 |
| `ImportExportController` | 向导、预览、问题定位、输出 | 文件格式解析和坐标算法 | GIS/导出阶段 |
| `WorkspaceController` | 打开、保存、恢复、布局和历史 | 独立实现第二份撤销栈 | 随服务入口改造 |

规则：UI 编排交互，算法保留在 planning/simulation，事务经过应用服务。若应用层职责变化需要增加依赖，先更新架构说明；不能让规划或仿真依赖 PySide6。

### 20.2 后台任务与一致性

- 统一后台作业 ID、输入版本、进度、取消标志和错误类型。
- 阻塞型 GIS/求解调用不能留在主线程。
- 取消信号必须传到可取消边界；无法立即终止的外部调用不再提交结果。
- 输出应用前检查项目 revision，过期结果只可留作候选记录。
- 日志包含阶段耗时，而非只有“规划完成”。
- 导入、求解和报告各自管理临时资源，失败不污染工程。

### 20.3 缓存设计

| 缓存 | Key 要素 | 失效原因 |
|---|---|---|
| 网格 | 地图范围、分辨率、几何版本 | 范围/分辨率/几何改变 |
| 障碍膨胀 | 障碍版本、半径、安全余量 | 机型或障碍改变 |
| DEM 采样 | 文件哈希、坐标、基准、分辨率、算法 | 数据或采样配置改变 |
| 航段路径 | 起终点、高度、机型空间参数、环境版本 | 空域、障碍或净空改变 |
| 时间/能源 | 路径、速度、载荷、风、模型版本 | 动力学或环境改变 |
| 坐标转换 | CRS、原点、轴和网格版本 | 地理配置改变 |
| 导出核验 | 输入/方案/资源/目标配置哈希 | 任一相关变化 |

设定容量上限、LRU 淘汰和命中率统计。浮点坐标量化不能悄悄降低安全精度；量化策略需有误差界。缓存开/关结果应语义相同。

### 20.4 空间索引

先记录碰撞查询、区域相交、地形采样的耗时比例，再选择四叉树或其他索引。

- 索引返回候选集合后仍执行精确几何核验。
- 编辑对象时更新索引或令其失效。
- 大区域、细小障碍和重叠边界都要覆盖。
- 不能因包围盒不相交的数值误差漏掉真实碰撞。
- 报告构建耗时、查询次数、候选数量与峰值内存。

### 20.5 D* Lite / LPA* 增量规划

D* Lite 的技术参考见第 24 章 R7。它作为路径代价局部更新的候选，不替代任务分配、时间窗或多机调度。

实施步骤：

1. 提取动态事件影响范围：新增障碍、临时禁飞、局部代价变化。
2. 区分图拓扑变化与仅边代价变化。
3. 保留可复用搜索状态，增量更新受影响节点。
4. 与全量 A* 在同样约束和目标下比较。
5. 更新范围过大、图版本不兼容或状态无效时回退全量搜索。
6. 新路径继续经过时间、能源和冲突复核。

验收使用同一批局部变化序列，比较正确性、扩展节点数和端到端耗时。只有在实际场景有收益时才默认开启，避免用更复杂算法换来更差维护性。

### 20.6 依赖治理

| 依赖 | 处置方向 |
|---|---|
| OR-Tools | 全局分配阶段正式使用并验证打包 |
| NumPy | 栅格批量计算确有收益时使用 |

同步维护 `pyproject.toml`、实际存在的依赖清单、打包脚本和开发文档。新增 GIS 原生库应尽早验证 EXE，不等所有功能完成后再处理 DLL 和数据目录。

### 20.7 错误、日志和观测

建议统一错误类别：输入无效、资源缺失、坐标不可转换、约束不可行、求解超时、结果过期、用户取消、导出不支持、内部错误。

性能日志按解析、重投影、建图、矩阵、求解、避碰、核验、应用结果分别记录。

### 21.3 属性测试范围

- 迁移幂等，保存/读取语义等价。
- 同一路线增加非负服务时长，不应提前其后续最早完成时刻。
- 放宽时间窗后，同一候选方案仍保持可行。
- 增加安全余量不会扩大同一几何核验器的可行空间。
- 相同输入、缓存开关不同，结果语义相同。
- 依赖 ID 均存在，所有已完成任务拥有相应实际事件。
- 有限范围内坐标往返满足已声明数值容差。
- 同时使用的机体、电池和工位资源不超过容量。

属性约束针对问题或固定候选；不要断言“启发式在同一墙钟时限内，放宽约束后一定找到更优解”，因为搜索行为不等同于可行域性质。

### 21.4 随机与模糊测试

- 几何：随机多边形、细长通道、边界接触、接近容差的点。
- 调度：紧窗口、长服务、交叉依赖、异构资源。
- 导入：缺字段、重复 ID、异常深度、大数组、损坏文件。
- 仿真：不同故障时刻、阵风、延迟、丢包和定位误差。
- 失败种子固化到仓库小样例，记录输入与预期行为。
- 为输入大小、解析深度、运行时长和内存设置上限。

| 场景 | 建议规模 | 建议预算 |
|---|---|---|
| 小型规划 | 3 机、20 任务 | 热缓存端到端约 3 s |

- 旧项目迁移无提示丢失任务、动作或路线。

- 主线已承诺目标配置没有地面站/SITL 证据。
- Windows 成品缺少运行必需库或数据。
- 报告状态超过实际验证级别。

### 23.3 模块完成定义

一个功能只有在以下条件满足时完成：

- 用户能够从实际入口使用，而不只是存在内部函数。
- 数据可保存、可重开，必要时有旧格式迁移。
- 正常、边界、无解、取消和错误场景都有结果。
- 硬约束进入规划并被最终核验，相关字段不是仅供显示。
- 地图、时间表、仿真和报告口径一致。
- 有明确测试证据，环境未运行不写成通过。
- 文档说明用途、参数、范围与限制。
