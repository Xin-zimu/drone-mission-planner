# Drone Mission Planner v1.3 — Crazyflie 真机联动完整开发计划

> 文档日期：2026-09-16  
> 文档状态：**可执行实施稿**  
> 适用仓库：`Xin-zimu/drone-mission-planner`  
> 前置版本：v1.2 主线 F0–F6 已完成；F7 完成并封版后开始本计划  
> v1.3 核心目标：**让 Drone Mission Planner 规划得到的单机航线，经安全校验后由真实 Crazyflie 执行，并将真实遥测、实际轨迹和执行结果回传到 Planner。**  
> 首版目标平台：Windows PySide6 Planner + Ubuntu/WSL2 ROS 2 Jazzy + Crazyswarm2 + Crazyradio + 单台 Crazyflie  
> 首版定位策略：优先支持 **Flow Deck V2 的局部相对坐标执行**；Lighthouse 作为后续增强；仅有 Z-Ranger/测高 ToF 时不得解锁自动 XYZ 航点飞行。

# 0. 一句话定义 v1.3

v1.2 解决：

```text
任务 → 分配 → 路径规划 → 航点 → 风险/导出校验
```

v1.3 解决：

```text
任务
 ↓
规划航线
 ↓
执行编译
 ↓
安全预检
 ↓
ROS 2 / Crazyswarm2
 ↓
Crazyradio
 ↓
真实 Crazyflie
 ↑
遥测 / 实际轨迹 / 执行结果
 └──────────────────────→ Drone Mission Planner
```

v1.3 **不是重写规划器**，而是在现有 Planner 后面增加“真实执行层”。

# 1. 版本目标与边界

## 1.1 v1.3 必须完成

v1.3 正式发布必须具备以下完整闭环：

1. Planner 能建立与 Crazyflie Execution Bridge 的连接。
2. Planner 能识别执行端能力、目标机器人和定位能力。
3. Planner 能把现有 `Drone.waypoints` 编译成独立的 Crazyflie Execution Mission。
4. 编译过程具有明确的坐标变换、动作映射、速度/时长约束和安全限制。
5. Crazyswarm2 `backend:=sim` 可以完整执行同一份 mission。
6. 真机 Crazyradio 连接、参数、遥测和定位能力可以被 Bridge 读取。
7. 真机飞行前必须通过 Preflight Gate。
8. 有可靠 XY 定位后，单台 Crazyflie 可以执行：
   - takeoff；
   - waypoint sequence；
   - hover/hold；
   - return/land；
   - operator abort → controlled land。
9. Planner 能实时显示：
   - bridge 连接状态；
   - robot 连接状态；
   -定位状态；
   - battery/status；
   - 当前执行状态；
   - 当前 waypoint；
   -真实 pose；
   -实际轨迹。
10. 执行完成后生成 Plan-vs-Actual 结果。
11. sim 与 hardware 使用同一上层 mission/state-machine 语义。
12. v1.3 的所有 core 功能都有 pytest 覆盖；ROS bridge 有自己的单元/集成测试。
13. 真实飞行必须留下可复核的运行日志。

## 1.2 v1.3 明确不做

以下功能不得在 v1.3 主线中扩张范围：

- 多 Crazyflie 同时执行；
- swarm formation；
- 多机实时避碰；
- 真正 3D 搜索算法重写；
- 动态障碍视觉感知；
- 在线 SLAM；
- 自动云端调度；
- 互联网远程无人值守飞行；
- MAVLink/PX4 控制链替换 Crazyflie 原生链路；
- Lighthouse 强依赖；
- 复杂 payload 控制；
- TAKE_PHOTO 对真实相机的硬件实现；
- SCAN 对真实传感器的硬件实现；
- 飞行中全局实时重规划。

这些内容进入 v1.4 或更后版本。

## 1.3 成功标准

v1.3 的最终演示必须是：

```text
在 Drone Mission Planner 中生成路线
        ↓
选择 Crazyflie Target
        ↓
连接 Execution Bridge
        ↓
Preflight PASS
        ↓
点击 Execute
        ↓
Crazyflie 自动起飞

        ↓
```

# 2. 当前仓库基线与必须保留的架构事实

## 2.1 现有路线单一来源不得破坏

当前项目已经明确：

```text
Drone.waypoints
= 路线唯一权威数据

Drone.planned_path
= waypoints 的只读二维派生
```

v1.3 禁止重新引入：

```text
hardware_route
ros_route
crazyflie_route
```

作为第二套可编辑航线源。

正确设计：

```text
Drone.waypoints
      ↓ compile
ExecutionMission
```

`ExecutionMission` 是**不可变执行快照**，不是新的规划事实源。

## 2.2 Planner core 不得依赖 ROS 2

必须维持：

```text
planning/
simulation/
domain/
execution/
```

均不依赖：

- `rclpy`
- `crazyflie_py`
- `cflib`
- ROS message class

原因：

1. Windows 主程序仍应可独立运行；
2. PyInstaller/Windows release 不应被 ROS 环境绑死；
3. v1.2 的纯 Python 测试必须继续可跑；
4. sim、hardware、未来其他飞控应通过 adapter 替换。

## 2.3 不复用 PX4/QGC ExportProfile 作为 Crazyflie 控制接口

F6 的 `ExportProfile` 面向：

```text
Planner → QGC/PX4 文件导出
```

v1.3 应新增：

```text
ExecutionTargetProfile
```

面向：

```text
Planner → 实时/半实时执行目标
```

两者可以共享设计思想，但不得强耦合。

## 3.2 为什么使用 TCP + NDJSON

v1.3 固定使用：

```text
TCP
+
一行一个 JSON object（NDJSON）
```

而不是让 Windows Planner 直接加入 ROS 2。

优点：

- Windows Planner 零 ROS 依赖；
- Qt 自带 `QTcpSocket`；
- Python bridge 可以直接实现；
- 可在 localhost、WSL、局域网复用；
- 容易抓包、记录、重放；
- 易写协议测试；
- 未来可替换成 WebSocket/gRPC，而不改变 execution domain。

## 3.3 默认网络安全边界

v1.3 默认：

```text
bind = 127.0.0.1
port = 8765
```

不得默认：

```text
0.0.0.0:8765
```

远程/LAN 模式后续显式开启。

v1.3 的目标不是互联网远程飞行。

## 5.1 ExecutionTargetProfile

新增强类型模型：

```python
@dataclass(frozen=True, slots=True)
class ExecutionTargetProfile:
    id: str
    name: str
    vehicle_family: str
    coordinate_frame: str
    max_waypoints: int
    max_speed_mps: float
    max_altitude_m: float
    max_radius_m: float
    supported_actions: frozenset[WaypointAction]
    requires_xy_positioning: bool
    requires_pose_stream: bool
    min_pose_rate_hz: float
    supports_live_telemetry: bool
```

首个 profile：

```text
id:
crazyflie-crazyswarm2-single-v1

vehicle_family:
Crazyflie 2.x

coordinate_frame:
local_world_m

supported actions:
FLY_TO
HOVER
LAND
RETURN_TO_LAUNCH
```

v1.3 第一版：

```text
TAKE_PHOTO → unsupported
SCAN       → unsupported 或 compile 为普通 FLY_TO，并明确 warning
```

不得静默忽略动作。

## 5.2 ExecutionWaypoint

```python
@dataclass(frozen=True, slots=True)
class ExecutionWaypoint:
    index: int
    x_m: float
    y_m: float
    z_m: float
    yaw_rad: float
    speed_mps: float
    duration_s: float
    action: str
    hold_s: float
    source_task_id: str | None
```

重要：

- `x_m/y_m/z_m` 已经是 **Crazyflie execution frame**；
- Bridge 不再猜 Planner 坐标含义；
- `duration_s` 在 Planner 编译阶段算好；
- Bridge 可以重新做 bounds validation，但不得任意改路线。

## 5.3 ExecutionMission

```python
@dataclass(frozen=True, slots=True)
class ExecutionMission:
    protocol_version: str
    mission_id: str
    project_name: str
    source_drone_id: str
    target_profile_id: str
    frame: ExecutionFrameCalibration
    created_at_utc: str
    waypoints: tuple[ExecutionWaypoint, ...]
    safety_limits: ExecutionSafetyLimits
    source_route_hash: str
```

要求：

- `mission_id` 唯一；
- mission 一经发送不得就地修改；
- Planner route 改变后生成新 mission；
- `source_route_hash` 用 SHA-256 对规范化航点 payload 哈希；
- Bridge 必须回传实际加载的 hash；
- hash 不一致不得 Execute。

## 5.4 ExecutionSafetyLimits

至少：

```python
@dataclass(frozen=True, slots=True)
class ExecutionSafetyLimits:
    max_horizontal_radius_m: float
    max_altitude_m: float
    max_speed_mps: float
    max_segment_duration_s: float
    waypoint_acceptance_radius_m: float
    pose_stale_timeout_s: float
    max_tracking_error_m: float
```

初期实验建议 profile 使用小范围限制，例如：

```text
max altitude        ≈ 1.0 m
max XY radius       ≈ 1.5–2.0 m
max speed           ≈ 0.5 m/s
```

这些值必须在 UI 中显示，并可配置，但第一次版本不允许无限制。

# 6. 坐标系设计

这是 v1.3 最关键的技术问题之一。

## 6.1 Planner 与 Crazyflie 不直接共享“原点”

Planner 内部：

```text
x = East / local X
y = North / local Y
z = Planner altitude semantics
```

Crazyflie：

```text
world/x
world/y
world/z
```

必须经过显式校准。

## 6.2 ExecutionFrameCalibration

```python
@dataclass(frozen=True, slots=True)
class ExecutionFrameCalibration:
    mode: str
    planner_origin_x_m: float
    planner_origin_y_m: float
    planner_origin_z_m: float
    cf_origin_x_m: float
    cf_origin_y_m: float
    cf_origin_z_m: float
    yaw_offset_rad: float
    validated: bool
```

v1.3 支持两种 mode：

### A. `relative_takeoff`

Flow Deck 首选。

把 Planner 的任务起点映射为 Crazyflie：

```text
(0, 0, 0)
```

计算：

```text
dx = planner_x - planner_origin_x
dy = planner_y - planner_origin_y
```

旋转：

```text
cf_x =  cos(yaw) * dx - sin(yaw) * dy
cf_y =  sin(yaw) * dx + cos(yaw) * dy
```

高度：

```text
cf_z = planner_z_normalized - planner_origin_z + cf_origin_z
```

### B. `absolute_local`

留给 Lighthouse/LPS/Mocap。

要求：

- 明确 world frame；
- 原点已校准；
- yaw alignment 已校准；
- validation 状态为 PASS。

## 6.3 Flow Deck 限制

Flow Deck 是相对定位。

因此 v1.3 Flow 模式规定：

1. mission 每次执行前以起飞点建立局部参考；
2. mission 半径保持较小；
3. 不把 WGS84/ENU 的“绝对地理意义”直接承诺给 Flow；
4. UI 明确显示：

```text
Execution frame: RELATIVE / FLOW
```

5. 不宣称厘米级全局坐标一致性。

# 7. 高度语义

Crazyflie `go_to(... z ...)` 的 `z` 是局部世界坐标高度，不是 MSL。

因此禁止：

```text
Waypoint.altitude(MSL)
→ 直接作为 Crazyflie z
```

必须通过编译。

## 7.1 编译规则

对于每个 waypoint：

1. 获取 Planner 中经过验证的实际高度语义；
2. 转换到 execution origin；
3. 得到 Crazyflie local Z；
4. 检查：
   - `z >= 0`
   - `z <= profile.max_altitude`
   - 没有 NaN/Inf
   - 相邻高度变化合理

## 7.2 Z-Ranger-only 情况

只有测高 ToF 时：

```text
height sensing = YES
XY positioning = NO
```

因此：

```text
connect            ✅
status             ✅
battery            ✅
height telemetry   ✅
hardware inspect   ✅

autonomous takeoff ❌ 默认锁定
go_to XY           ❌
route execution    ❌
```

不要因为能读到 `z` 就把机器人标记为 `POSITIONING_READY`。

# 8. Mission Compiler

新增：

```text
execution/mission_compiler.py
```

入口：

```python
compile_crazyflie_mission(
    project: ProjectModel,
    drone: Drone,
    profile: ExecutionTargetProfile,
    frame: ExecutionFrameCalibration,
) -> ExecutionMission
```

## 8.1 编译流程

固定顺序：

```text
Drone.waypoints
 ↓
结构检查
 ↓
动作能力检查
 ↓
坐标变换
 ↓
高度归一化
 ↓
速度裁剪/拒绝
 ↓
duration 计算
 ↓
半径/高度/速度限制
 ↓
mission hash
 ↓
ExecutionMission
```

## 8.2 duration 计算

Crazyflie 高层 `go_to` 需要 duration。

对于 segment：

```text
distance = 3D distance(prev, current)

requested_speed =
    waypoint.speed
    or profile/default speed

duration =
    distance / requested_speed
```

再施加：

```text
min_segment_duration
max_segment_duration
```

不能让 `duration <= 0`。

## 8.3 禁止重叠 go_to

Bitcraze 高层 commander 不应在上一条 `go_to` 尚未完成时再发送新的 `go_to`。

因此 Executor 必须：

```text
send go_to
 ↓
等待 planned duration
 ↓
检查 pose 已进入 acceptance radius
 ↓
settle
 ↓
发送 next go_to
```

不能：

```python
for wp in mission:
    send_go_to(wp)
```

瞬间全部发完。

# 9. Planner ↔ Bridge 协议

协议版本：

```text
dmp-cf/1
```

编码：

```text
UTF-8 NDJSON
```

每条消息：

```json
{"type":"...", "request_id":"...", "...":"..."}
```

## 9.1 Planner → Bridge

必须支持：

```text
hello
ping
get_capabilities
select_robot
load_mission
run_preflight
execute_mission
abort_land
emergency_stop
clear_mission
```

v1.3 暂不要求：

```text
pause
resume
dynamic_replan
multi_robot_execute
```

## 9.2 Bridge → Planner

必须支持：

```text
hello_ack
pong
capabilities
robot_state
preflight_report
mission_loaded
mission_state
waypoint_state
telemetry
event
error
```

## 9.3 请求幂等性

所有会改变状态的 command 必须带：

```text
request_id
mission_id（若相关）
```

Bridge 在短时间缓存已处理 request_id。

同一 request 重发时不得重复起飞。

## 9.4 Heartbeat

Planner 每：

```text
1 s
```

发送 ping。

Bridge 若连接丢失：

- 不立即 Emergency；
- 若尚未飞行：保持 safe idle；
- 若正在飞行：进入 `CONTROL_LINK_LOST` 策略；
- 默认策略为完成当前 segment 后 controlled land，或立即 controlled land，具体由配置指定；
- 不允许因为 Planner UI 崩溃就无限继续任务。

# 10. ROS 2 / Crazyswarm2 Adapter

## 10.1 Adapter 接口

`mission_executor.py` 不直接散落 ROS 调用。

定义：

```python
class CrazyflieAdapter(Protocol):
    def connect(self) -> None: ...
    def disconnect(self) -> None: ...
    def capabilities(self) -> RobotCapabilities: ...
    def latest_state(self) -> RobotState: ...
    def takeoff(self, height_m: float, duration_s: float) -> None: ...
    def go_to(
        self,
        x_m: float,
        y_m: float,
        z_m: float,
        yaw_rad: float,
        duration_s: float,
    ) -> None: ...
    def land(self, height_m: float, duration_s: float) -> None: ...
    def emergency(self) -> None: ...
```

实现：

```text
Crazyswarm2Adapter
```

以后才能扩展：

```text
MockAdapter
ReplayAdapter
```

## 10.2 ROS 2 使用原则

优先通过：

- `crazyflie_py`；
- `crazyflie_interfaces`；
- Crazyswarm2 server 提供的标准 topic/service。

禁止：

- shell 拼接 `ros2 service call` 作为正式执行方式；
- subprocess 控制每一个 waypoint；
- Planner 直接操作 cflib；
- UI 直接发送 CRTP。

# 11. Bridge 状态机

必须建立显式状态机。

```text
OFFLINE
  ↓
BRIDGE_READY
  ↓
ROBOT_CONNECTED
  ↓
POSITIONING_CHECK
  ↓
POSITIONING_READY
  ↓
MISSION_LOADED
  ↓
PREFLIGHT_PASSED
  ↓
READY_TO_EXECUTE
  ↓
TAKING_OFF
  ↓
EXECUTING
  ↓
HOLDING (optional)
  ↓
RETURNING
  ↓
LANDING
  ↓
LANDED
```

异常：

```text
ANY FLIGHT STATE
  ↓
ABORTING
  ↓
LANDING
```

严重故障：

```text
ANY
 ↓
FAULT
```

人工 Emergency：

```text
AIRBORNE
 ↓
EMERGENCY
```

## 11.1 Emergency 与 Abort 必须分开

### Abort

默认安全按钮：

```text
ABORT / LAND
```

含义：

```text
停止继续任务
→ controlled land
```

### Emergency

危险的最后手段：

```text
EMERGENCY MOTOR STOP
```

UI 要：

- 红色；
- 二次确认；

2. 目标 Crazyflie connected。
3. mission_id/hash 与 Planner 一致。

5. profile 匹配。
6. 没有 unsupported action。
7. 坐标 calibration 已 validated。
8. XY positioning capability 可用。
9. pose stream 可用。
10. pose freshness 合格。
11. estimator 状态稳定。
12. mission 全部 waypoint 在安全半径内。
13. altitude 不超过限值。
14. speed 不超过限值。
15. 当前飞机位置与 mission start 距离不超过允许偏差。
16. 没有 active execution。
17. operator 已显式解锁飞行。

# Appendix A — 官方技术事实依据

本计划依赖以下官方接口事实：

1. Crazyswarm2 是 ROS 2 Crazyflie stack，包含 Crazyflie server、`crazyflie_py`、interfaces 和 simulator。
2. Crazyswarm2 server 提供 Takeoff / Land / GoTo / trajectory / Emergency 等高层接口。
3. Crazyswarm2 `sim` 使用 Crazyflie firmware SIL，并提供与 server 一致的 ROS interface。
4. Crazyswarm2 支持 Ubuntu 24.04 + ROS 2 Jazzy。
5. WSL 通过 `usbipd-win` 为 experimental support。
6. Crazyflie High Level Commander 的 `go_to(x,y,z,yaw,duration)` 使用米制位置和时间。
7. 官方特别警告不要重叠发送 `go_to`，否则生成轨迹可能出现异常高峰。
8. Crazyswarm2 可记录 `pose`、`odom`、`status`、`imu` 等 telemetry。
9. Flow Deck V2 使用 PMW3901 optical flow + VL53L1x ToF，并将数据融合进 Crazyflie EKF，可用于局部三维预编程运动。
10. Z-Ranger 类 ToF 只能补充高度测量，不等价于完整 XY positioning。

# Appendix B — 核心设计结论

本计划最重要的架构决策只有七条：

1. **不改 Planner 的规划事实源：`Drone.waypoints` 继续唯一权威。**
2. **Windows Planner 不安装、不导入 ROS 2。**
3. **新增独立 ROS 2 Crazyflie Bridge。**
4. **Planner ↔ Bridge 固定 TCP + NDJSON 协议。**
5. **所有真机路线先编译为不可变 `ExecutionMission`。**
6. **没有 XY positioning，自动飞行硬阻断。**
7. **先 Crazyswarm2 SIM，再 props-off 真机通信，再定位，再真实飞行。**

如果后续实现偏离其中任意一条，必须先更新本文并记录 architecture decision，而不是静默改变架构。
