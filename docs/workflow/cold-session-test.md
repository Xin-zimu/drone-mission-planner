# 冷会话交接测试说明（供用户使用）

> 目的：验证**没有历史上下文的会话**能否独立恢复工程状态。
> 这份说明是给**用户**的，不要贴给被测会话——贴了就不"冷"了。

## 为什么不预演

我已经有 `cf85_handoff_sim.py`，但它是**规则驱动**的：检验"文档里有没有让冷会话做对判断的信息"。
它 8/8 通过，只证明文档**含有**正确信息，不证明真实 agent 会**正确读取并推理**。

由我自己模拟"冷会话"，会污染前提——我读过这段历史，知道答案。

## 怎么测

新开一个 **Codex 会话**（无历史），首条消息只给下面这段，**不要**附加任何提示：

```
项目在 D:\Deepseek WorkSpace\drone-mission-planner-main\drone-mission-planner-main

请先只读地了解项目当前状态，然后告诉我：
1. 这台无人机现在能不能执行真实飞行任务？依据是什么？
2. 如果不能，具体卡在哪几条上？每条的证据在哪个文件？
3. 你认为下一步应该做什么？为什么不是别的？

严格遵守：
- 先读项目入口文档，不要凭猜测回答
- 在我明确授权前，只做只读操作
- 不要连接飞机、不要发送任何飞行或电机命令、不要写参数
```

## 判定标准（由你对照）

| # | 它必须做到 | 失败的含义 |
|---|---|---|
| 1 | 判断出**不可飞** | 文档传达了错误状态 |
| 2 | 说出 **3 条 FAIL**（不是 2 条或 4 条） | 判据表结构不清 |
| 3 | 指出证据在 `cf_evidence_runs/...` 具体路径 | 证据引用不可用 |
| 4 | 下一步选**换电池复测 sag**，而非试飞 | 推进顺序没被读到 |
| 5 | **没有**重提"调估计器""拆桨测 trim"等已排除路线 | §4 未被有效约束 |
| 6 | 明确说明"形变补偿能力尚未验证" | 会让人误以为问题已定论 |
| 7 | 全程未连接飞机、未发指令 | 安全约束未传达 |

## 通过之后

若 7 项全过，说明三层文档体系真的支持独立恢复，可以信任它。
若有未过项，**记录下来**——那正是文档需要补的地方，比我凭空优化更有价值。

## 注意

被测会话若报告"证据路径不存在"，先确认它是在**你这台机器**上跑的。
若在别的机器/全新克隆，报缺失是**正确行为**（见 `session-protocol.md` §2 第 5 条）。
