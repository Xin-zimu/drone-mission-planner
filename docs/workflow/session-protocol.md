# 会话工作流协议（一切会话的入口）

> 本文件是**任何新会话的第一份必读文档**。它替代散装的 `CF8_*_handoff_*.md` 与
> `NEXT_SESSION_*_PROMPT*.txt`（这些已归档到 `docs/archive/`）。
> 规则：**先读本文件 → 再按任务线读对应规范 → 核对会话日志 → 才能动手。**

## 0. 这套体系的文档地图

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| **本文件** `docs/workflow/session-protocol.md` | 会话启动节奏、报告格式、通用铁律 | 每次会话必读 |
| `docs/workflow/session-log.md` | **唯一**的当前状态页（git HEAD、硬件、阻断点、最近会话） | 每次会话必读 |
| `docs/workflow/cf8-operations.md` | CF8 真机线规范：SOP、故障库、工具索引、环境坑 | 涉及真机时必读 |
| `docs/workflow/dev-workflow.md` | 软件研发线规范（扩展 AGENTS.md 的执行细节） | 写产品代码时必读 |
| `AGENTS.md`（仓库根） | Codex 15 条开发铁律 | 写代码前必读 |
| `docs/archive/` | 历史交接文档，**只查历史，不作为事实基线** | 需要还原旧决策时 |

**权威优先级（冲突时）：会话日志 > 本协议与各规范 > 历史归档。**
任何规范与现实不符时：**先修正规范再动手**，不允许"按印象绕过去"。

---

## 1. 会话启动节奏（每个新会话照做，约 5 分钟，全部只读）

1. **读会话日志** `docs/workflow/session-log.md`：当前 git HEAD、未提交文件、硬件状态、
   当前阻断点、上轮结论、待办。
2. **核对 git**（只读）：
   ```powershell
   git -C "D:\dmp" status --short
   git -C "D:\dmp" log --oneline -3
   ```
   期望值以会话日志为准。发现工作树与日志不一致 → **先报告，不动手**。
3. **按任务线读规范**：真机线读 `cf8-operations.md`；代码线读 `dev-workflow.md`。
4. **对齐目标**：用一句话复述本轮要做什么，请用户确认后再动手。
   （历史上的"目的迷糊"问题靠这一步根治：每轮开工前必须与用户对齐目标。）

**禁止**：跳过上述步骤直接"从头分析"；重复跑历史诊断；在没读会话日志的情况下
修改任何文件或发送任何命令。

---

## 2. 会话收尾节奏（会话结束前必做，除非用户明确喊停）

1. **更新会话日志** `docs/workflow/session-log.md`：git HEAD、本轮改动、硬件状态变化、
   阻断点变化、结论、下一步待办。
2. **确认交接完整性**：下一个会话只读 `session-log.md` + 对应规范能否恢复上下文？
   不能 → 把缺失事实补进日志。
3. **git 提交**：本协议相关文档与产品代码分开提交（见 dev-workflow.md §3）。
4. **明确收尾声明**：报告本轮是否发送过 arm / takeoff / land / go_to / emergency
   （真机线必须逐项 YES/NO），是否写过机体 NVM，是否修改过阈值。

---

## 3. 报告格式（所有线通用）

每轮报告固定结构：

```markdown
## 本轮结论（先行，一句话）
## 执行了什么（命令 + 关键输出）
## 改动了什么（文件清单；未改动就写"无"）
## 验证结果（测试/探针/读数）
## 安全声明（真机线必填）
- arm / takeoff / land / go_to / emergency：YES / NO（逐项）
- NVM 写入：YES / NO　阈值修改：YES / NO　真实飞行：YES / NO
## 下一步
```

**语言：中文。不要只给建议，要实际检查、修改、测试、推进。**

---

## 4. 通用铁律（所有线）

1. **单一事实来源**：状态以 `session-log.md` 为准；流程以规范为准；不新造平行文档。
2. **发现规范与现实不符 → 先改规范**，提交时把"规范修正"单独说明。
3. **一次会话一个主线目标**；目标变了先更新会话日志再继续。
4. **不重复诊断**：故障库（`cf8-operations.md` §6）里有的签名，先对照，再动手。
5. **工具不爆炸**：新脚本必须进 `_dsh_scratch/` 且命名 `cf85_` 前缀 + 用途可猜；
   写完立即登记进 `cf8-operations.md` §5 工具表；一次性脚本用完标注 `[临时]` 并删除。
6. **环境坑只写一次**：环境坑统一记在 `cf8-operations.md` §7；新坑先验证再入表。
7. **Windows 命令注意**：路径含空格时用 `D:\dmp`（junction）；PowerShell 内联
   不写 `$`（会提前展开），shell 逻辑写进 `.sh`。
8. **不自动重试任何 gate/飞行**；FAIL 即停、报告、等指示。
