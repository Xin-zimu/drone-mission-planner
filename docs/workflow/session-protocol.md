# 会话工作流协议（一切会话的入口）

> 本文件是**任何新会话的第一份必读文档**。它替代散装的 `CF8_*_handoff_*.md` 与
> `NEXT_SESSION_*_PROMPT*.txt`（这些已归档到 `docs/archive/`）。
> 规则：**先读本文件 → 再按任务线读对应规范 → 核对会话日志 → 才能动手。**

## 0. 这套体系的文档地图

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| **本文件** `docs/workflow/session-protocol.md` | 会话启动节奏、报告格式、通用铁律 | 每次会话必读 |
| `docs/workflow/PLAN.md` | **总计划**：项目到哪去、什么算完成、不做什么 | 每次会话必读（很少改） |
| `docs/workflow/STAGE.md` | **当前阶段计划**：阶段目标、完成判据（挂实测证据）、前置条件、已排除路线 | 每次会话必读 |
| `docs/workflow/session-log.md` | **当前状态快照**：现在能不能飞、卡在哪、下一步 | 每次会话必读（每轮重写） |
| `docs/workflow/cf8-operations.md` | CF8 真机线规范：SOP、故障库、工具索引、环境坑 | 涉及真机时必读 |
| `docs/workflow/dev-workflow.md` | 软件研发线规范（扩展 AGENTS.md 的执行细节） | 写产品代码时必读 |
| `AGENTS.md`（仓库根） | Codex 15 条开发铁律 | 写代码前必读 |
| `docs/archive/` | 历史交接与旧计划，**只查历史，不作为事实基线** | 需要还原旧决策时 |

**权威优先级（冲突时）：STAGE 的完成判据 > session-log > 本协议与各规范 > 历史归档。**
任何规范与现实不符时：**先修正规范再动手**，不允许"按印象绕过去"。

> **三层计划的分工（不要混）**：
> - `PLAN.md` 回答"项目要到哪去"——**只有项目方向或总体验收标准变化时才改**。
> - `STAGE.md` 回答"这个阶段怎么算完成"。**两种更新分开对待**：
>   - **判据数据**：每产生一次有效实测就更新对应行（含测试条件 + 证据路径），**不等阶段结束**；
>   - **阶段定义**（目标/范围/判据本身）：只在阶段目标改变时改。
> - `session-log.md` 回答"现在卡在哪"——**每轮重写**。
>
> 不存在"接下来执行文档"：下一步写在 `STAGE.md` §5 的推进顺序里。多一份文档就多一个漂移点。
>
> **实验历史不靠文档保存，靠证据目录。** 原始数据（`recorder.ndjson`、`takeoff1.ndjson`、
> `battery.json` 等）在 `D:\Deepseek WorkSpace\cf_evidence_runs\<时间戳>-<阶段>\`，
> `STAGE.md` 的判据表里写**证据路径**指向它们。文档只留当前结论 + 条件 + 路径三条。

### 0.1 铁律：文档里不允许存在"两个互相矛盾的活结论"

2026-10-20 的教训——同一份日志里并存"已离地"与"未离地"两种结论，新会话读到哪条全看运气。
因此：

1. **`session-log.md` 是快照，不是编年史。** 每次收尾**重写**它（只留当前真相），
   不追加"补充""追加""更正"小节。
2. **被推翻的结论必须从当前文档删除**，不是加个"以上作废"就完事。过程写进
   `docs/archive/session-history-<日期>.md`。
3. **一个事实只有一个权威位置**。其他文档引用它时写"见 X"，不复制数值。
4. **故障库条目合并而不是加后缀**：已有 F2 就别造 F2b/F2c，直接在 F2 下写全。
   条目内按"当前有效的判据"组织，历史归因差异写在条目末尾一行。

**自检**：写完文档后问自己一句——"新会话只读这一页，会不会得出已被推翻的结论？"

## 1. 会话启动节奏（每个新会话照做，约 5 分钟，全部只读）

1. **读三层文档，顺序不能反**：
   - `PLAN.md` —— 项目到哪去、什么算完成（知道"为什么做"）
   - `STAGE.md` —— 本阶段完成判据 + **已排除的路线**（知道"哪些别再试"）
   - `session-log.md` —— 现在卡在哪、下一步（知道"今天做什么"）
2. **核对 git**（只读）：
   ```powershell
   git -C "D:\dmp" status --short
   git -C "D:\dmp" log --oneline -3
   ```
   期望值以会话日志为准。发现工作树与日志不一致 → **先报告，不动手**。
3. **按任务线读规范**：真机线读 `cf8-operations.md`；代码线读 `dev-workflow.md`。
4. **复述阶段判据**：开工前说明"本阶段四条判据现在分别是什么状态"，
   以及"本轮打算推进哪一条"。判据不成立时**不得**跳过去做后续步骤。
5. **对齐目标**：用一句话复述本轮要做什么，请用户确认后再动手。

**禁止**：跳过上述步骤直接"从头分析"；重复跑历史诊断；在没读会话日志的情况下
修改任何文件或发送任何命令；**重试 `STAGE.md` §4 已排除的路线**。

---

## 2. 会话收尾节奏（会话结束前必做，除非用户明确喊停）

1. **重写 `session-log.md`**：只描述**当前**的 git HEAD、阻断点、硬件实测、待办。
   **不追加新小节**；旧内容若属过程，先 `cp` 到 `docs/archive/session-history-<日期>.md`
   再整体重写。
2. **更新 `STAGE.md` 的判据**（本轮有实测就必做，不等阶段结束）：
   把**实测值 + 测试条件 + 证据路径 + 下一步**写进那张详情表，不是写"已完成"三个字。
   判据全绿 → 阶段完成 → 整份重写为下一阶段。
3. **`PLAN.md` 通常不动**。只有当用户改变项目目标、或完成标准本身需要修订时才改。
4. **清理矛盾**：本轮如果推翻了某个旧结论，**回到原文档把那段删掉或改写**。
   留着"以上作废"会让下一个人读到旧结论。
   **新结论进 `STAGE.md` §4 时必须带条件**（假设/条件/结果/结论/何时重评），
   不得写成"永远无效"这类无条件断言。
5. **跑三个自检**（已入仓库，可移植；证据根目录自动向上查找，可用 `$CF_EVIDENCE_ROOT` 覆盖）：
   ```bash
   python scripts/docs/cf85_doc_consistency.py   # 形式：引用 / 编年史化 / 阈值漂移
   python scripts/docs/cf85_stage_audit.py       # 事实：判据是否带条件+证据、FAIL 是否被闸住
   python scripts/docs/cf85_handoff_sim.py       # 交接：冷会话能否判断状态并选出下一步
   ```
   **注意边界**：这三个查的是"文档是否自洽、可交接"，**查不出"物理结论是否成立"**。
   它们全绿 ≠ 飞机达标。而且第 3 个是**规则驱动的模拟**，不能代替真实冷会话验证。
   实物验证只能靠真机实测；交接验证最终要靠一个没有历史上下文的真实新会话。
6. **git 提交**：本协议相关文档与产品代码分开提交（见 dev-workflow.md §3）。
7. **明确收尾声明**：报告本轮是否发送过 arm / takeoff / land / go_to / emergency
   （真机线必须逐项 YES/NO），是否写过机体 NVM，是否修改过阈值。

## 3. 报告格式（所有线通用）

每轮报告固定结构：

```markdown
## 本轮结论（先行，一句话）
## 执行了什么（命令 + 关键输出）
## 改动了什么（文件清单；未改动就写"无"）
## 验证结果（测试/探针/读数）
## 安全声明（真机线必填）
- arm / takeoff / land / go_to / emergency：YES / NO（逐项）
- NVM 写入：YES / NO　阈值修改：YES / NO　真实飞行：YES / NO
## 下一步
```

**语言：中文。不要只给建议，要实际检查、修改、测试、推进。**

---

## 4. 通用铁律（所有线）

1. **单一事实来源**：状态以 `session-log.md` 为准；流程以规范为准；不新造平行文档。
2. **发现规范与现实不符 → 先改规范**，提交时把"规范修正"单独说明。
3. **一次会话一个主线目标**；目标变了先更新会话日志再继续。
4. **不重复诊断**：故障库（`cf8-operations.md` §6）里有的签名，先对照，再动手。
5. **工具不爆炸**：新脚本必须进 `_dsh_scratch/` 且命名 `cf85_` 前缀 + 用途可猜；
   写完立即登记进 `cf8-operations.md` §5 工具表；一次性脚本用完标注 `[临时]` 并删除。
6. **环境坑只写一次**：环境坑统一记在 `cf8-operations.md` §7；新坑先验证再入表。
7. **Windows 命令注意**：路径含空格时用 `D:\dmp`（junction）；PowerShell 内联
   不写 `$`（会提前展开），shell 逻辑写进 `.sh`。
8. **不自动重试任何 gate/飞行**；FAIL 即停、报告、等指示。
