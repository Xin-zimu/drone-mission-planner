# v1.3 Crazyflie Software Acceptance

Date: 2026-09-18

Branch: `codex/v1.3-crazyflie-execution`

## Scope

This report accepts the v1.3 Crazyflie work as a software/SIM milestone only.
It does not accept real Crazyflie autonomous flight.

## Accepted Software Capabilities

- Pure-Python execution domain, target profile, mission compiler and preflight validation.
- Planner-to-bridge TCP + NDJSON protocol helpers and Qt execution client.
- ROS 2 bridge package skeleton with SIM backend and deterministic mission executor.
- Safe SIM takeoff, hover, waypoint, return-to-launch and landing state machine.
- Preflight-required execution gate, duplicate execute protection and structured errors.
- Abort/controlled-land path separated from explicit operator emergency stop.
- Deterministic handling for stale pose, robot disconnect, bridge disconnect, tracking error and mission timeout.
- Plan-vs-actual report conversion, JSON/CSV export and Execution Dock summary rendering.
- Non-flight hardware visibility probe that never enables motor commands.

## Hardware Acceptance

Status: PENDING

No real `takeoff`, `go_to`, `land` or emergency motor command has been sent by
this development run. Real hardware acceptance remains blocked until:

- ROS 2/Crazyswarm2 dependencies are available in the bridge runtime.
- Crazyflie/Crazyradio connection is verified through Crazyswarm2.
- Battery, deck/status and pose telemetry are streaming.
- Reliable XY positioning is verified with Flow Deck V2, Lighthouse or equivalent.
- The CF7 positioning gate has concrete telemetry evidence.
- A supervised hardware takeoff/hover/land run passes before waypoint execution.

## Known Limitation

On this Windows host, combined pytest runs can terminate inside the native
OR-Tools extension. Observed failures include `0xc000001d` illegal instruction
in `tests/integration/test_examples.py::test_regional_emergency_example_exercises_advanced_features`
and an access violation in `tests/unit/test_optimization.py::test_baseline_is_never_replaced_by_a_worse_candidate`.
The same optimization test file passes when run in isolation, and the failures
are outside the Crazyflie bridge/reporting path.
